## Кратко:

- **Всё работает на вашем железе.** Чат, рассуждения, генерация изображений и видео, голос, поиск по документам и веб-поиск — никаких облачных сервисов на пути обработки; единственное исключение — опциональный веб-поиск через Tavily.
- **Одна очередь GPU со строгой сериализацией.** Между GPU-задачами VRAM безусловно очищается; модель загружается только после того, как предыдущая выгружена.
- **Что делать — решает LLM-роутер.** Каждое сообщение классифицируется в одну из одиннадцати категорий — маршрутизации по ключевым словам в коде нет нигде.
- **Мультимодальность, многоязычность, память.** Изображения и отсканированные PDF читает модель зрения, интерфейс на русском и английском, а долговременная память сохраняется между сессиями.
- **Публичный OpenAI-совместимый API.** `/v1/chat/completions`, эмбеддинги, медиа, аудио, файлы и RLM, с персональными ключами и интерактивной справкой на `/v1/docs`. Чат с несколькими изображениями, глубокий анализ с изображениями и референсные изображения («нарисуй что-то похожее») работают через API так же, как в веб-чате.
- **GPU или CPU.** 8 ГБ VRAM достаточно для базового стека; большие модели и видео в полноразмерном качестве требуют больше VRAM. Режим только CPU поддерживает тот же набор функций, медленнее, с автоматическим снижением разрешения медиа.
- **Одна команда для развёртывания.** `./deploy-ru.sh --download-models --with-image-gen …` собирает образы, скачивает модели и запускает всё.

## ✨ Возможности

### 💬 Чат и рассуждения
- **Интеллектуальный чат** — роутер отправляет простые вопросы быстрой модели, а сложные — выделенной модели рассуждений.
- **Нативный вызов инструментов** — калькулятор, текущее время, арифметика дат, веб-поиск, поиск по документам, поиск по истории, чтение страниц и снимки камеры, с прогрессом в реальном времени.
- **Глубокий анализ (RLM)** — модель рассуждений пошагово прорабатывает выбранные документы и прикреплённое изображение, с изолированным исполнителем Python, вызовами подмоделей, живыми запросами и разворачиваемой трассировкой. → [DEEP_ANALYSIS-ru.md](docs/DEEP_ANALYSIS-ru.md)
- **Стили ответов** — нейтральный, академический, деловой, дружеский или весёлый; переключаются в шапке чата.
- **Сессии и экспорт** — несколько диалогов с автозаголовками, экспорт в HTML со встроенными медиа.

### 🎨 Медиа
- **Генерация изображений** — stable-diffusion.cpp с автоматической оптимизацией промпта. → [IMAGE_GENERATION-ru.md](docs/IMAGE_GENERATION-ru.md)
- **Редактирование изображений** — загрузите изображение и попросите о правках: цвета, удаление объектов, новые стили.
- **Генерация видео — два бэкенда.** LTX-Video 2B (быстро, до 10 с) или Wan 2.2 TI2V 5B (медленнее, 5 с, лучше движение), оба по текстовому промпту или промпту с изображением. → [VIDEO-ru.md](docs/VIDEO-ru.md)

### 🔎 Поиск и знания
- **Веб-поиск** — самостоятельно размещённый метапоисковик SearXNG плюс опциональный Tavily, с извлечением содержимого страниц, когда сниппеты слишком короткие. → [SEARCH-ru.md](docs/SEARCH-ru.md)
- **Поиск по документам (RAG)** — PDF, DOC, DOCX, TXT, ODT, RTF, CSV, JSON, EPUB, индексируются в Qdrant; каждому проиндексированному файлу гарантированно достаётся место в контексте. **Гибридный поиск** (векторы + полнотекст со слиянием RRF, включён по умолчанию) и необязательный **CPU-реранкер** закрывают вопросы про сущности, которые векторы пропускают. → [DOCUMENTS-ru.md](docs/DOCUMENTS-ru.md)
- **Папки документов** — одноуровневые папки в панели «Документы»: создание, переименование и удаление (удаление папки удаляет и документы в ней); перемещение кнопкой или перетаскиванием; групповые операции — перемещение и удаление (плашка показывает суммарный размер); загрузка сразу в папку. Те же чекбоксы при включённом переключателе 🔬 формируют корпус для глубокого анализа. → [DOCUMENTS-ru.md](docs/DOCUMENTS-ru.md)
- **OCR отсканированных PDF** — страницы без извлекаемого текста рендерятся и расшифровываются моделью зрения перед индексацией.
- **Чтение сайтов и глубокое изучение** — откройте одну ссылку или обойдите целый сайт и сохраните его как индексируемый документ.

## 🔎 Как работать с поиском по документам

В поиске по документам несколько слоёв. Какой из них оправдывает свою цену, зависит от вопроса:

| Вопрос | Лучший инструмент | Почему |
|---|---|---|
| Понятийный или перефразированный | **Векторный поиск** (работает всегда) | ищет по смыслу, а не по словам, и не добавляет задержки |
| Точные имена, города, артикулы, названия инструментов — или один большой файл топит остальные | **Гибридный поиск** (включён по умолчанию) | добавляет полнотекстовый поиск PostgreSQL с русской морфологией и сливает его с векторами через RRF; лексическая половина срабатывает только когда в вопросе есть редкий терм |
| Нужный фрагмент находится, но стоит вторым-третьим | **Реранкер** (выключен по умолчанию) | CPU-кросс-энкодер переупорядочивает верхних кандидатов; выигрывает в узких окнах, теряет в качестве на широких и добавляет ~0,3 с |
| «Перечисли все…», «сколько…», сравнить все записи документа | **Глубокий анализ** (🔬 с выбранными документами) | проходит по всему корпусу пошагово вместо одного фиксированного окна контекста |
| Важна только часть корпуса | **Область поиска** (🔍) | убирает конкурирующие документы до поиска — обычно самый сильный рычаг |
| Резюме, договоры, логи и другие файлы из записей | **Структурная нарезка** | держит одну логическую запись в одном фрагменте, поэтому перечисление и подсчёт остаются возможными |

Как пользоваться:

1. **Сначала сузьте область** — папка и/или период загрузки убирают конкурирующие документы ещё до
   поиска, и это даёт больше, чем любая настройка ранжирования. Область видна чипом и действует на
   следующие сообщения; документ, прикреплённый к сообщению, виден всегда, даже вне области.
2. **Гибридный поиск оставьте включённым** — он помогает на именах, артикулах и больших файлах за
   десятки миллисекунд; выключать его имеет смысл только на очень маленьком корпусе, где лексическая
   половина ничего не добавляет.
3. **Реранкер включайте точечно** — когда нужный фрагмент стабильно оказывается вторым-третьим, а окно
   контекста узкое (мало фрагментов). На широком окне (пара десятков фрагментов) он снижает качество
   ранжирования и добавляет ~0,3 с; «Кандидатов на реранк» держите на 10.
4. **Нарезку выбирайте по форме документа** — `structured` для резюме, договоров и логов, `recursive`
   или `fixed` для сплошного текста; после смены стратегии документы надо переиндексировать
   (`flask rag-reindex --user <login>`).
5. **Переключайтесь на глубокий анализ, когда ответ — список или подсчёт** по документу: обычный поиск
   отдаёт лучшие фрагменты, а не весь документ.

Каждый слой замеряется встроенным харнессом, а не включается на веру: `flask rag-eval` показывает
hit@k, MRR, nDCG и задержку, а журнал решений — в [RAG_EVAL-ru.md](docs/RAG_EVAL-ru.md) вместе с
устройством слоёв в [DOCUMENTS-ru.md](docs/DOCUMENTS-ru.md).

### 🧠 Память и контекст
- **Долговременная память (SLM)** — извлечение фактов по правилам (rule-based) и их слияние только на CPU с семантической дедупликацией; профиль на каждого пользователя, стирается вместе с учётной записью. → [MEMORY-ru.md](docs/MEMORY-ru.md)
- **Бюджетирование контекста** — реальная стоимость в токенах, а не догадки: сначала факты SLM, затем поиск, затем скользящее резюме, затем история. → [CONTEXT-ru.md](docs/CONTEXT-ru.md)
- **Счётчики токенов по каждому запросу** — в шапке каждого ответа видны реальные токены вывода и ввода. → [ARCHITECTURE-ru.md](docs/ARCHITECTURE-ru.md)

### 🗣️ Голос, камера и веб-интерфейс
- **Голосовые сообщения** — транскрипция Whisper ASR.
- **Синтез речи** — Piper (лёгкий) или Kokoro (качественнее), выбирается при развёртывании; голос — мужской или женский. → [VOICE-ru.md](docs/VOICE-ru.md)
- **Снимки с камеры (опционально)** — запросите кадр с IP-камеры и проанализируйте его моделью зрения, с правами доступа для каждого пользователя. → [CAMERA-ru.md](docs/CAMERA-ru.md)
- **Вложения** — до 4 изображений, один документ или до 4 аудиозаписей (одно голосовое сообщение и аудиофайлы: 1 голосовое + 3 файла или 4 файла) в одном сообщении чата. Изображения показываются миниатюрами высотой не больше кнопки «Отправить»; документы, аудио и голос — эмодзи-чипами 📄/🎵/🎤. Документ индексируется в RAG, чтобы модель могла отвечать по нему; несколько изображений анализируются вместе (сравнение/групповые вопросы); каждая аудиозапись распознаётся по порядку и получает ответ. Вставка из буфера (Ctrl+V) пополняет очередь. → [DOCUMENTS-ru.md](docs/DOCUMENTS-ru.md)
- **Видимость очереди** — живая позиция и индикаторы стадий, полосы прогресса, отмена задач, метки непрочитанного.
- **HTML-блоки** — запускайте сгенерированный HTML из сообщения в изолированной вкладке предпросмотра.

### 🔌 API и автоматизация
- **Персональные API-ключи** — создаются в веб-интерфейсе, хранятся как дайджесты SHA-256, отзываются.
- **OpenAI-совместимый `/v1`** — chat completions (синхронно и через SSE), асинхронный чат, эмбеддинги, генерация изображений и видео, синтез и транскрипция речи, файлы и документы, RLM, сессии и опрос задач с проверкой владельца. API принимает запросы чата с несколькими изображениями, изображения для глубокого анализа и референсные изображения для генерации (до 4 изображений, один совместный вызов зрения).
- **Интерактивная справка** — Swagger UI на `/v1/docs`, документ OpenAPI на `/v1/openapi.json`, отдаётся офлайн со встроенными ресурсами. → [API-ru.md](docs/API-ru.md)

### ⚙️ Администрирование
- **Пользователи** — создание, правка, удаление, классы обслуживания, права на камеры, лимиты хранилища (действуют на всех путях загрузки) и счётчик интернет-запросов за месяц.
- **Модели** — выбор и настройка GGUF-моделей для каждого модуля; контекстное окно, не помещающееся в железо, отклоняется.
- **Model Hub** — поиск GGUF-моделей на Hugging Face, оценка по VRAM/RAM до скачивания, скачивание с прогрессом и докачкой, удаление того, что больше не нужно.
- **Резервные копии** — полная копия или копия по пользователю, восстановление из админ-панели.
- **Персонализация** — свой логотип в шапке и локализованные названия сайта; всё это входит в полные резервные копии.
- **Мониторинг** — обзор оборудования и баз данных плюс вкладка использования: хранилище, сессии, сообщения, задачи, токены, файлы, документы и запросы в интернет по пользователям за 1 ч – 30 дней. → [MONITORING-ru.md](docs/MONITORING-ru.md)
- **CLI-инструменты** — пароль администратора, очистка загрузок, миграция формата сообщений, импорт и очистка SLM. → [DEVELOPMENT-ru.md](docs/DEVELOPMENT-ru.md)

### 🔒 Приватность и безопасность
- 100% локальная обработка; за пределы вашей сети не уходит ничего, кроме поисковых сервисов, которые вы настроили.
- Аутентификация сессий с хешированием пароля, cookie HttpOnly/SameSite, CSRF на каждой форме, ограничение частоты попыток входа и ведение аудит-лога.
- Строгая изоляция сессий, сообщений, документов и доступа к камерам между пользователями.
- Задачи очереди Redis подписаны HMAC; пути файлов проверяются на обход каталогов; весь HTML из markdown очищается с помощью DOMPurify.
- Каждый URL, уходящий из приложения, проходит проверку на SSRF — приватные, петлевые (loopback), link-local и CGNAT-адреса отклоняются.

## 🏗 Обзор архитектуры

```
Браузер / клиент API
        │
        ▼
   Flask-приложение (app/) ──► PostgreSQL   сообщения, сессии, пользователи, документы
        │              Redis        очередь, события (SSE), лимиты частоты, реестр задач
        │              Qdrant       векторы документов
        ▼
  Очередь запросов (app/queue.py)
        │
        ├── быстрый воркер (CPU) ──► роутинг, инструменты, поиск RAG, веб-поиск, STT, TTS, эмбеддинги
        └── медленный воркер (GPU) ──► мультимодальность · рассуждения · изображения · видео      ← по одному
                                  ▲
                          _gpu_lock (единственный)
                                  │
   modules/ ── llama.cpp (мультимодальность, рассуждения, эмбеддинги) · sd.cpp (+ видео Wan) · LTX-Video
          ── Whisper · Piper/Kokoro · SearXNG/Tavily/Crawl4AI · SuperLocalMemory
```

Правила, которые важнее всего:

1. **GPU-работа строго сериализована.** Каждая GPU-задача берёт единственный `_gpu_lock`; после каждой задачи выгружаются все модели llama.cpp, освобождается видеоконвейер и очищается кэш CUDA.
2. **Деградация происходит до загрузки.** `compute_llamacpp_config()` уменьшает `n_gpu_layers`, пока модель не поместится; если она не помещается даже на CPU, задача завершается ошибкой вместо падения с OOM.
3. **Извлечение никогда не генерирует.** Быстрый воркер только извлекает. Ответы производит модель рассуждений на медленном воркере.
4. **Маршрутизация — всегда через LLM.** Никаких списков ключевых слов, никаких шаблонов, никаких жёстко заданных запросов.

Подробности: [ARCHITECTURE-ru.md](docs/ARCHITECTURE-ru.md) · [VRAM_MANAGEMENT-ru.md](docs/VRAM_MANAGEMENT-ru.md).

## 🧭 Типы запросов и механизмы поиска

Каждое сообщение модель роутера классифицирует в одну из этих категорий. Категория определяет, что выполняется до ответа и какой контекст добавляется в промпт.

| Категория (маркер) | Маршрут | Что выполняется | Что попадает в промпт |
|---|---|---|---|
| `[-RAG-]` | **Поиск по документам** | Векторный поиск в Qdrant (эмбеддинги + порог релевантности) | Фрагменты RAG + факты SLM + резюме сессии + история |
| `[-SEARCH-]` | **Веб-поиск** | Сначала Tavily (персональный ключ), затем SearXNG (параллельная загрузка, извлечение текста) | Результаты веб-поиска (~30% бюджета) + SLM + резюме + история |
| `[-HISTORY-]` | **Поиск по истории** | Ранжированный полнотекстовый поиск PostgreSQL по прошлым сессиям | Фрагменты истории + SLM + резюме + текущая сессия |
| `[-REASONING-]` | **Сложные рассуждения** | Напрямую модель рассуждений, без внешних данных | Факты SLM + резюме + история |
| `[-REASONING-WEB-]` | **Рассуждения со свежими данными** | Веб-поиск → рассуждение по результатам | Результаты веб-поиска + SLM + резюме + история |
| `[-CRAWL-]` | **Глубокое изучение сайта** | Crawl4AI обходит сайт → заменяет документ домена → индексирует его → строит рассуждение по корпусу | Обойдённые страницы как секции `## <url>` (с ограничением бюджетом) + SLM + резюме + история |
| `[-CAMERA-]` | **Снимок с камеры** | API снимков комнаты забирает текущий кадр; модель зрения анализирует его | Описание снимка + SLM + история |
| `[-REMEMBER-]` | **Запомнить факт** | Извлечение SLM по правилам (в фоне, только CPU) | — (пишет в долговременную память) |
| `[-IMAGE-]` / `[-VIDEO-]` | **Генерация медиа** | stable-diffusion.cpp (изображения и видео Wan) / LTX-Video в собственных GPU-контейнерах | — (без LLM-контекста) |
| `none` | **Чат с инструментами** | Мультимодальная модель + нативный вызов инструментов | Результаты инструментов + SLM + история |

**Как это работает на практике:**

- RAG, веб-поиск и поиск по истории взаимно исключают друг друга — на один запрос работает один механизм поиска.
- Сообщение с **одной** ссылкой и вопросом об этой странице («что за проект <URL>») — это обычный чат: инструмент `read_page` открывает её. Глубокое изучение сайта нужно только для явных запросов по всему сайту.
- Роутер сначала определяет **время действия**: запросы о прошлом («мы смотрели», «ты показывал раньше») уходят в поиск по истории, а категории камеры, изображения и видео покрывают только действия, которые нужно выполнить сейчас.
- Классификация видит небольшой **микроконтекст сессии** — последние несколько настоящих (не служебных) сообщений и до двух долговременных фактов, — поэтому на вопрос «мы смотрели картинки с камеры?» ответ приходит из истории, а камера не включается снова.
- Вызовы инструментов в режиме `none` выполняются на быстром воркере и транслируют прогресс в реальном времени.
- Маршрутизации по ключевым словам в коде нет нигде.

Полный промпт роутера и ярлыки стадий: [ARCHITECTURE-ru.md](docs/ARCHITECTURE-ru.md).

## 📋 Системные требования

### Два режима развёртывания

- **Режим GPU (NVIDIA, CUDA 12.2+)** — рекомендуемый режим. Весь стек работает на CUDA-сборках с NVIDIA Container Toolkit.
- **Режим только CPU** — тот же набор функций без GPU. Всё медленнее, поэтому генерация изображений и видео автоматически снижает разрешение, чтобы уложиться во временной бюджет.

> ⚠️ **Официальный стек compose не поддерживает GPU от AMD и Intel** — готовые образы собраны только под CUDA. Для гарантированного результата используйте режим только CPU.

### Уровни оборудования

| Компонент | Минимальный | Средний | Полный | Только CPU |
|-----------|-----------|----------|------|----------|
| **VRAM GPU** | 8 ГБ | 12 ГБ | 16+ ГБ | — |
| **RAM (минимум)** | 16 ГБ | 24 ГБ | 24 ГБ | 16 ГБ (24 ГБ с медиа) |
| **RAM (рекомендуется)** | 24 ГБ | 32 ГБ | 32 ГБ | 48 ГБ |
| **CPU** | 4+ ядра | 6+ ядер | 6+ ядер | 8+ ядер (рекомендуется 12) |
| **Хранилище** | 60 ГБ | 80+ ГБ SSD | 100+ ГБ SSD NVMe | 100+ ГБ SSD NVMe |

### Сколько стоит каждый профиль

Каждый сервис — это профиль compose. Ниже **измеренные** значения, а не оценки: это те числа,
на которых работает планировщик в `resource_manager.py`. Их нужно прибавить к базовому уровню.

| Профиль | RAM | VRAM | Примечания |
|---|---|---|---|
| **Ядро** (web, PostgreSQL, Redis, Qdrant, SearXNG, Crawl4AI, простаивающий llama-swap) | ~2,5 ГБ | — | одновременно резидентна одна модель llama.cpp |
| **Piper TTS** (`with-voice-piper`) | **~0,5 ГБ** | — | измерено со всеми четырьмя голосами |
| **Kokoro TTS** (`with-voice-kokoro`) | **1,6 ГБ в покое / ~4,5 ГБ прогретый** | — | +3,1 ГБ — это RU-воркер G2P, освобождается через `KOKORO_G2P_IDLE_TIMEOUT` (300 с) |
| **Whisper ASR** (`with-voice-*`) | ~2 ГБ | — | `large-v3-turbo`, CPU; планировщик резервирует `WHISPER_RAM_MB` |
| **Генерация изображений** (`with-image-gen`) | ~1,5 ГБ | до ~10 ГБ | sd.cpp, Z-Image Turbo Q8; SD и видео никогда не пересекаются |
| **LTX-Video** (`with-video`) | ~1 ГБ резидентно | **пик 3,1 ГБ** | измеренный пик конвейера, а не прежняя константа 8 ГБ |
| **Wan видео** (`with-video-wan`) | ~1 ГБ (GPU) / **~10 ГБ** при выгруженном энкодере | **15,0 ГБ** на 832×480×121; **9,0 ГБ** с `--offload-to-cpu` | измерено 209 с на 5-секундный клип на карте 16 ГБ |
| **SuperLocalMemory** (`with-slm`) | ~0,5 ГБ (бюджет планировщика 2 ГБ) | — | эмбеддинги на CPU |
| **Реранкер** (опция, по умолчанию выключен) | ~0,9 ГБ | — | `bge-reranker-v2-m3`, группа `cpu_only`, не занимает слот GPU |

Профили TTS взаимоисключающие (Piper — по умолчанию, Kokoro — вариант качества), как и профили
видео (LTX — по умолчанию, Wan — вариант качества). Оба TTS-бэкенда считают на CPU на любом
уровне, включая GPU-хосты, поэтому VRAM они не занимают.

Одновременно резидентна только одна модель llama.cpp, поэтому бюджет RAM складывается из ОС,
PostgreSQL/Redis, веб-приложения и слоёв, вынесенных на CPU для рассуждений на малых GPU. В режиме
только CPU стартовый стек лёгкий: модель рассуждений ~11 ГБ и мультимодальная модель ~2,5 ГБ.
Генерации видео нужен собственный запас памяти: на CPU она доминирует (планирование LTX
начинается с ~17,4 ГБ статики и понижает формат, чтобы уложиться и в RAM, и во временной
бюджет), а Wan там отклоняется полностью — 5-секундный клип 480p: одна секунда 256×192 заняла
98 с, а любой осмысленный размер требует больше 12 ГБ RAM.

- Сервер Linux, Docker Engine ≥ 20.10, Docker Compose ≥ 2.0

### Совместимость драйверов CUDA

`deploy-ru.sh` читает драйвер хоста и выбирает подходящие образы. **Минимальная поддерживаемая версия CUDA: 12.2 (драйвер 525.60.13+).**

| Версия CUDA (ветка драйвера) | Образы | Примечания |
|------------------------------|--------|-------|
| ≥ 13.0 | CUDA 13.0.1 + `llama-swap:v267-cuda13-b11889` | Стандартно |
| 12.8 – 12.9 | CUDA 12.8.1 (Ubuntu 24.04) | Стандартно |
| 12.6 – 12.7 | CUDA 12.6.3 (Ubuntu 24.04) | Требования NVIDIA к образу отключены (`NVIDIA_DISABLE_REQUIRE=1`) |
| 12.4 – 12.5 | CUDA 12.4.1 (Ubuntu 22.04) | Требования NVIDIA к образу отключены (`NVIDIA_DISABLE_REQUIRE=1`) |
| **12.2 – 12.3 (минимум)** | CUDA 12.2.2 (Ubuntu 22.04) | Требования NVIDIA к образу отключены для всех GPU-сервисов (`NVIDIA_DISABLE_REQUIRE=1`) |

llama-swap зафиксирован намеренно: в upstream-репозитории формат конфигурации изменился в версии 243, и плавающий тег ломает свежие развёртывания. Ниже 12.2 скрипт отказывается от режима GPU и переходит на режим только CPU.

## 🚀 Быстрый старт

> 💡 Для развёртывания на GPU нужны **драйверы NVIDIA** и **NVIDIA Container Toolkit**.

### Вариант A — автоматический (рекомендуется)

Один скрипт создаёт `.env` с безопасными секретами, скачивает модели, собирает образы и запускает всё.

```bash
git clone https://github.com/barval/flai.git
cd flai

# Ядро: чат, зрение, рассуждения, вызов инструментов
./deploy-ru.sh --download-models

# + генерация и редактирование изображений
./deploy-ru.sh --download-models --with-image-gen

# + голос — выберите ОДИН бэкенд (Piper по умолчанию, --with-voice — алиас)
./deploy-ru.sh --download-models --with-image-gen --with-voice-piper
./deploy-ru.sh --download-models --with-image-gen --with-voice-kokoro

# + поиск по документам (Qdrant)
./deploy-ru.sh --download-models --with-image-gen --with-voice-piper --with-rag

# + генерация видео — выберите ОДИН бэкенд
#   LTX: быстро, клипы до 10 с (по умолчанию)
#   Wan: медленнее, 5 с, лучше движение (только GPU)
./deploy-ru.sh --download-models --with-image-gen --with-voice-piper --with-rag --with-video
./deploy-ru.sh --download-models --with-image-gen --with-voice-piper --with-rag --with-video-wan

# + долговременная память, + веб-поиск, + краулер сайтов
./deploy-ru.sh --download-models --with-image-gen --with-voice-piper --with-rag \
  --with-video --with-slm --with-search --with-crawler

# Прогнать набор тестов после развёртывания
./deploy-ru.sh --download-models --with-image-gen --run-tests
```

Нет NVIDIA GPU? Добавьте `--cpu`; тогда автоматически выбирается `docker-compose.cpu.yml`. Переключение между GPU и CPU не требует пересборки — образы имеют теги по бэкенду (CPU/GPU) и сосуществуют локально.

### Вариант B — ручной

```bash
git clone https://github.com/barval/flai.git
cd flai

sudo mkdir -p data data/uploads data/documents
sudo chown -R 1000:1000 data
cp .env.example .env
```

Сгенерируйте два секрета и задайте часовой пояс, URL и настройки:

```bash
sed -i "s|^SECRET_KEY=.*|SECRET_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")|" .env
sed -i "s|^QDRANT_API_KEY=.*|QDRANT_API_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")|" .env
nano .env
```

Скачайте модели в `services/*/models/`. Полный список файлов, размеров, лицензий и команд `wget` — в [MODELS-ru.md](docs/MODELS-ru.md); Model Hub в админ-панели может скачать их за вас с прогрессом и докачкой.

Запустите сервисы — каждый профиль необязателен:

```bash
# Чат, зрение, рассуждения, инструменты (базовый стек)
docker compose -f docker-compose.gpu.yml up -d

# Добавить подсистемы
docker compose -f docker-compose.gpu.yml \
  --profile with-image-gen --profile with-voice-piper --profile with-rag \
  --profile with-video --profile with-slm --profile with-search --profile with-crawler up -d

# Хосты без GPU используют другой файл compose
docker compose -f docker-compose.cpu.yml up -d
```

> ⏱️ Первая сборка компилирует stable-diffusion.cpp из исходников и занимает время; последующие сборки используют кэш.

Задайте пароль администратора и откройте инстанс:

```bash
docker exec flai-web flask admin-password YourSecurePassword123
```

Затем откройте `http://localhost:5000` и войдите как `admin`:

1. **Админ-панель → Модели** — подтвердите мультимодальную модель, модель рассуждений и модель эмбеддингов; при необходимости поправьте параметры. Контекстное окно, не помещающееся в бюджет RAM/VRAM, отклоняется при сохранении, а фоновая пробная загрузка (dry-load) откатывает конфигурацию, если загрузка не удалась.
2. **Админ-панель → Пользователи** — создайте учётные записи и назначьте классы обслуживания и права на камеры.
3. **Отправьте первое сообщение** — роутер сам выберет подсистему. Прикрепите документ, изображение или голосовое сообщение, чтобы увидеть другие сценарии.
