## Кратко:

- **Всё работает на вашем железе.** Чат, рассуждения, генерация изображений и видео, голос, поиск по документам и веб-поиск — облачный сервис только по желанию (опциональный Tavily для веб-поиска).
- **Одна очередь GPU со строгой сериализацией.** Между GPU-задачами VRAM безусловно очищается; модель загружается только после того, как предыдущая выгружена.
- **Что делать — решает LLM-роутер.** Каждое сообщение классифицируется в одну из одиннадцати категорий — маршрутизации по ключевым словам в коде нет нигде.
- **Мультимодальность, многоязычность, память.** Изображения и отсканированные PDF читает модель зрения, интерфейс русско-английский, а долговременная память переживает сессии.
- **Публичный OpenAI-совместимый API.** `/v1/chat/completions`, эмбеддинги, медиа, аудио, файлы и RLM, с персональными ключами и интерактивной справкой на `/v1/docs`.
- **GPU или CPU.** 8 ГБ VRAM достаточно для базового стека; большие модели и видео в полноразмерном качестве требуют больше VRAM. Режим только CPU даёт те же функции, медленнее, с автоматическим снижением разрешения медиа.
- **Одна команда для развёртывания.** `./deploy.sh --download-models --with-image-gen …` собирает образы, скачивает модели и запускает всё.

## 🆕 Что нового в v12.4

- **Мультивложения в чате** — до 4 изображений в одном сообщении одним вызовом модели зрения (с запасным путём по одному), а документ, приложенный прямо в чат, индексируется в RAG — модель отвечает по нему. Вложения показываются чипами: миниатюры для картинок, 🎤/🎵/📄 для голоса/аудио/документов. → [DOCUMENTS-ru.md](docs/DOCUMENTS-ru.md)
- **Глубокий анализ с вложениями** — переключатель 🔬 принимает до 4 изображений (каждое становится «документом» корпуса) и документы, приложенные к чату, поэтому выбор в панели «Документы» не обязателен. → [DEEP_ANALYSIS-ru.md](docs/DEEP_ANALYSIS-ru.md)
- **«Нарисуй что-то похожее» с примерами** — приложите изображения-примеры к запросу генерации: каждое описывается, и описания направляют промпт SD. → [IMAGE_GENERATION-ru.md](docs/IMAGE_GENERATION-ru.md)
- **Повышенные лимиты** — документы 25 МБ, хранилище документов 250 МБ на пользователя, тело запроса 75 МБ; OCR отсканированных PDF получает бюджет 30 минут на документ с уведомлением о частичном распознавании. → [CONFIGURATION-ru.md](docs/CONFIGURATION-ru.md)
- **Веб-поиск сначала через Tavily** — каждый пользователь может привязать бесплатный персональный ключ Tavily (1000 кредитов в месяц) во всплывающем окне профиля. Поиск сначала пробует Tavily, а при любой ошибке переходит на локальный движок SearXNG, поэтому исчерпанный лимит или неверный ключ никогда не ломают поиск. → [SEARCH-ru.md](docs/SEARCH-ru.md)
- **Веб-краулер (Crawl4AI)** — опциональный sidecar открывает вставленную ссылку в настоящем браузере (`read_page`), а по явному запросу «изучи этот сайт» обходит домен (≤50 страниц, глубина ≤3, бюджет 5 минут), заменяет документ домена, индексирует его обычным RAG-конвейером и отвечает по нему — в том числе в режиме глубокого анализа. → [SEARCH-ru.md](docs/SEARCH-ru.md)
- **Увеличены таймауты для CPU** — генерации изображений в режиме только CPU отведено 45 минут, видео — 2 часа, поэтому медленная генерация медиа завершается, а не умирает на шаге 3/10. → [TROUBLESHOOTING-ru.md](docs/TROUBLESHOOTING-ru.md)
- **Единый источник версии** — окно «О системе» раскрывает название проекта, а строка версии берётся из одной константы. → [RELEASE_GUIDE-ru.md](docs/RELEASE_GUIDE-ru.md)

## ✨ Возможности

### 💬 Чат и рассуждения
- **Интеллектуальный чат** — роутер отправляет простые вопросы быстрой модели, а сложные — выделенной модели рассуждений.
- **Нативный вызов инструментов** — калькулятор, текущее время, арифметика дат, веб-поиск, поиск по документам, поиск по истории, чтение страниц и снимки камеры, с прогрессом в реальном времени.
- **Глубокий анализ (RLM)** — модель рассуждений пошагово прорабатывает выбранные документы и прикреплённое изображение, с изолированным исполнителем Python, вызовами подмоделей, живыми запросами и разворачиваемой трассировкой. → [DEEP_ANALYSIS-ru.md](docs/DEEP_ANALYSIS-ru.md)
- **Стили ответов** — нейтральный, академический, профессиональный, дружелюбный или шуточный; переключаются в шапке чата.
- **Сессии и экспорт** — несколько диалогов с автозаголовками, экспорт в HTML со встроенными медиа.

### 🎨 Медиа
- **Генерация изображений** — stable-diffusion.cpp с автоматической оптимизацией промпта. → [IMAGE_GENERATION-ru.md](docs/IMAGE_GENERATION-ru.md)
- **Редактирование изображений** — загрузите изображение и попросите о правках: цвета, удаление объектов, новые стили.
- **Генерация видео** — LTX-Video 2B, 8-шаговый дистиллированный инференс, текстовый промпт или изображение с текстом. → [VIDEO-ru.md](docs/VIDEO-ru.md)

### 🔎 Поиск и знания
- **Веб-поиск** — самостоятельно размещённый метапоисковик SearXNG плюс опциональный Tavily, с извлечением содержимого страниц, когда сниппеты слишком короткие. → [SEARCH-ru.md](docs/SEARCH-ru.md)
- **Поиск по документам (RAG)** — PDF, DOC, DOCX, TXT, ODT, RTF, CSV, JSON, EPUB, индексируются в Qdrant; каждому проиндексированному файлу гарантированно достаётся место в контексте. → [DOCUMENTS-ru.md](docs/DOCUMENTS-ru.md)
- **OCR отсканированных PDF** — страницы без извлекаемого текста рендерятся и расшифровываются моделью зрения перед индексацией.
- **Чтение сайтов и глубокое изучение** — откройте одну ссылку или обойдите целый сайт в индексируемый документ.

### 🧠 Память и контекст
- **Долговременная память (SLM)** — правиловое извлечение и слияние фактов только на CPU с семантической дедупликацией; профиль на каждого пользователя, стирается вместе с учётной записью. → [MEMORY-ru.md](docs/MEMORY-ru.md)
- **Бюджетирование контекста** — реальная стоимость в токенах, а не догадки: сначала факты SLM, затем поиск, затем скользящее резюме, затем история. → [CONTEXT-ru.md](docs/CONTEXT-ru.md)
- **Счётчики токенов по каждому запросу** — в шапке каждого ответа видны реальные токены вывода и ввода. → [ARCHITECTURE-ru.md](docs/ARCHITECTURE-ru.md)

### 🗣️ Голос, камера и веб-интерфейс
- **Голосовые сообщения** — транскрипция Whisper ASR.
- **Синтез речи** — Piper (лёгкий) или Kokoro (качественнее), выбирается при развёртывании, мужской или женский голос. → [VOICE-ru.md](docs/VOICE-ru.md)
- **Снимки с камеры (опционально)** — запросите кадр с IP-камеры и проанализируйте его моделью зрения, с правами доступа для каждого пользователя. → [CAMERA-ru.md](docs/CAMERA-ru.md)
- **Вложения** — до 4 изображений, один документ, аудио или голосовое сообщение в одном сообщении чата; картинки прикрепляются миниатюрами (не выше кнопки «Отправить»), документы/аудио/голос — эмодзи-чипами 📄/🎵/🎤. Документ индексируется в RAG, чтобы модель могла отвечать по нему; несколько картинок анализируются вместе (сравнение/групповые вопросы). Вставка из буфера (Ctrl+V) пополняет очередь. → [DOCUMENTS-ru.md](docs/DOCUMENTS-ru.md)
- **Видимость очереди** — живая позиция и индикаторы стадий, полосы прогресса, отмена задач, метки непрочитанного.
- **HTML-блоки** — запускайте сгенерированный HTML из сообщения в изолированной вкладке предпросмотра.

### 🔌 API и автоматизация
- **Персональные API-ключи** — создаются в веб-интерфейсе, хранятся как дайджесты SHA-256, отзываются.
- **OpenAI-совместимый `/v1`** — чат-комплишены (синхронно + SSE), асинхронный чат, эмбеддинги, генерация изображений и видео, синтез и транскрипция речи, файлы и документы, RLM, сессии и опрос задач с проверкой владельца.
- **Интерактивная справка** — Swagger UI на `/v1/docs`, документ OpenAPI на `/v1/openapi.json`, отдаётся офлайн со встроенными ресурсами. → [API-ru.md](docs/API-ru.md)

### ⚙️ Администрирование
- **Пользователи** — создание, правка, удаление, классы сервисов, права на камеры.
- **Модели** — выбор и настройка GGUF-моделей для каждого модуля; контекстное окно, не помещающееся в железо, отклоняется.
- **Model Hub** — поиск GGUF-моделей на Hugging Face, оценка по VRAM/ОЗУ до скачивания, скачивание с прогрессом и докачкой, удаление того, что больше не нужно.
- **Резервные копии** — полная копия или копия по пользователю, восстановление из админ-панели.
- **Персонализация** — свой логотип в шапке и локализованные названия сайта, попадают в полные бэкапы.
- **Мониторинг** — обзор оборудования, размеры баз данных, системная статистика. → [MONITORING-ru.md](docs/MONITORING-ru.md)
- **CLI-инструменты** — пароль администратора, очистка загрузок, миграция формата сообщений, импорт и очистка SLM. → [DEVELOPMENT-ru.md](docs/DEVELOPMENT-ru.md)

### 🔒 Приватность и безопасность
- 100% локальная обработка; за пределы вашей сети не уходит ничего, кроме поисковых сервисов, которые вы настроили.
- Аутентификация сессий с хешированием пароля, cookie HttpOnly/SameSite, CSRF на каждой форме, ограничение частоты попыток входа и журналирование аудита.
- Строгая изоляция сессий, сообщений, документов и доступа к камерам между пользователями.
- Задачи очереди Redis подписаны HMAC; пути файлов проверяются на обход каталогов; весь HTML из markdown очищается DOMPurify.
- Каждый URL, уходящий из приложения, проходит SSRF-гард (никаких приватных, loopback, link-local и CGNAT-адресов).

## 🏗️ Обзор архитектуры

```
Браузер / клиент API
        │
        ▼
   Flask-приложение (app/) ──► PostgreSQL   сообщения, сессии, пользователи, документы
        │              Redis        очередь, события (SSE), лимиты частоты, реестр задач
        │              Qdrant       векторы документов
        ▼
  Очередь запросов (app/queue.py)
        │
        ├── быстрый воркер (CPU) ──► роутинг, инструменты, поиск RAG, веб-поиск, STT, TTS, эмбеддинги
        └── медленный воркер (GPU) ──► мультимодальность · рассуждения · изображения · видео      ← по одному
                                  ▲
                          _gpu_lock (единственный)
                                  │
   modules/ ── llama.cpp (мультимодальность, рассуждения, эмбеддинги) · sd.cpp · LTX-Video
          ── Whisper · Piper/Kokoro · SearXNG/Tavily/Crawl4AI · SuperLocalMemory
```

Правила, которые важнее всего:

1. **GPU-работа строго сериализована.** Каждая GPU-задача берёт единственный `_gpu_lock`; после каждой выгружаются все модели llama.cpp, освобождается видеоконвейер и очищается кэш CUDA.
2. **Деградация происходит до загрузки.** `compute_llamacpp_config()` уменьшает `n_gpu_layers`, пока модель не поместится; если она не помещается даже на CPU, задача завершается ошибкой вместо падения с OOM.
3. **Извлечение никогда не генерирует.** Быстрый воркер только извлекает. Ответы производит модель рассуждений на медленном воркере.
4. **Маршрутизация — всегда через LLM.** Никаких списков ключевых слов, никаких шаблонов, никаких жёстко заданных запросов.

Подробности: [ARCHITECTURE-ru.md](docs/ARCHITECTURE-ru.md) · [VRAM_MANAGEMENT-ru.md](docs/VRAM_MANAGEMENT-ru.md).

## 🧭 Типы запросов и механизмы поиска

Каждое сообщение модель роутера классифицирует в одну из этих категорий. Категория определяет, что выполняется до ответа и какой контекст добавляется в промпт.

| Категория (маркер) | Маршрут | Что выполняется | Что попадает в промпт |
|---|---|---|---|
| `[-RAG-]` | **Поиск по документам** | Векторный поиск в Qdrant (эмбеддинги + фильтр по оценке) | Фрагменты RAG + факты SLM + резюме сессии + история |
| `[-SEARCH-]` | **Веб-поиск** | Сначала Tavily (персональный ключ), затем SearXNG (параллельная загрузка, извлечение текста) | Результаты веб-поиска (~30% бюджета) + SLM + резюме + история |
| `[-HISTORY-]` | **Поиск по истории** | Ранжированный полнотекстовый поиск PostgreSQL по прошлым сессиям | Фрагменты истории + SLM + резюме + текущая сессия |
| `[-REASONING-]` | **Сложные рассуждения** | Напрямую модель рассуждений, без внешних данных | Факты SLM + резюме + история |
| `[-REASONING-WEB-]` | **Рассуждения со свежими данными** | Веб-поиск → рассуждение по результатам | Результаты веб-поиска + SLM + резюме + история |
| `[-CRAWL-]` | **Глубокое изучение сайта** | Crawl4AI обходит сайт → заменяет документ домена → индексирует его → рассуждает над корпусом | Обойдённые страницы как секции `## <url>` (с ограничением бюджетом) + SLM + резюме + история |
| `[-CAMERA-]` | **Снимок с камеры** | API снимков комнаты забирает текущий кадр; модель зрения анализирует его | Описание снимка + SLM + история |
| `[-REMEMBER-]` | **Запомнить факт** | Правиловое извлечение SLM (фоном, только CPU) | — (пишет в долговременную память) |
| `[-IMAGE-]` / `[-VIDEO-]` | **Генерация медиа** | stable-diffusion.cpp / LTX-Video в собственных GPU-контейнерах | — (без LLM-контекста) |
| `none` | **Чат с инструментами** | Мультимодальная модель + нативный вызов инструментов | Результаты инструментов + SLM + история |

**Как это работает на практике:**

- RAG, веб-поиск и поиск по истории взаимно исключают друг друга — на один запрос работает один механизм поиска.
- Сообщение с **одной** ссылкой и вопросом об этой странице («что за проект <URL>») — это обычный чат: инструмент `read_page` открывает её. Глубокое изучение сайта нужно только для явных запросов по всему сайту.
- Роутер сначала определяет **время действия**: запросы о прошлом («мы смотрели», «ты показывал раньше») уходят в поиск по истории, а категории камеры, изображения и видео покрывают только действия, которые нужно выполнить сейчас.
- Классификация видит небольшой **микроконтекст сессии** — последние реальные сообщения и до двух долговременных фактов, — поэтому на вопрос «мы смотрели картинки с камеры?» ответ приходит из истории, а камера не включается снова.
- Вызовы инструментов в режиме `none` выполняются на быстром воркере и транслируют прогресс в реальном времени.
- Маршрутизации по ключевым словам в коде нет нигде.

Полный промпт роутера и ярлыки стадий: [ARCHITECTURE-ru.md](docs/ARCHITECTURE-ru.md).

## 📋 Системные требования

### Два режима развёртывания

- **Режим GPU (NVIDIA, CUDA 12.2+)** — рекомендуемый режим. Весь стек работает на CUDA-сборках с NVIDIA Container Toolkit.
- **Режим только CPU** — тот же набор функций без GPU. Всё медленнее, поэтому генерация изображений и видео автоматически снижает разрешение, чтобы уложиться во временной бюджет.

> ⚠️ **Официальный стек compose не поддерживает GPU от AMD и Intel** — предсобранные образы только под CUDA. Для гарантированного результата используйте режим только CPU.

### Уровни оборудования

| Компонент | Минимальный | Средний | Полный | Только CPU |
|-----------|-----------|----------|------|----------|
| **VRAM GPU** | 8 ГБ | 12 ГБ | 16+ ГБ | — |
| **ОЗУ (минимум)** | 16 ГБ | 24 ГБ | 24 ГБ | 24 ГБ |
| **ОЗУ (рекомендуется)** | 24 ГБ | 32 ГБ | 32 ГБ | 48 ГБ |
| **ЦП** | 4+ ядра | 6+ ядер | 6+ ядер | 8+ ядер (рекомендуется 12) |
| **Хранилище** | 60 ГБ | 80+ ГБ SSD | 100+ ГБ SSD NVMe | 100+ ГБ SSD NVMe |

Одновременно резидентна только одна модель llama.cpp, поэтому бюджет ОЗУ — это ОС плюс PostgreSQL/Redis плюс веб-приложение, плюс слои, выгруженные на CPU для рассуждений на небольших GPU. В режиме только CPU стартовый стек лёгкий: модель рассуждений ~11 ГБ и мультимодальная модель ~2,5 ГБ. Генерации видео нужен собственный запас — на CPU она доминирует, и планировщик понижает формат, чтобы уложиться и в ОЗУ, и во временной бюджет.

### Что работает на каждом уровне

| Функция | 8 ГБ | 12 ГБ | 16+ ГБ | Только CPU |
|---------|------|-------|--------|----------|
| Чат + зрение (Qwen3VL) | ✅ 4B (лёгкая) | ✅ 8B | ✅ 8B | ✅ 4B (лёгкая) |
| Рассуждения | ⚠️ частичная выгрузка на CPU (~15–20 ток/с) | ✅ ~70–90 ток/с | ✅ ~107 ток/с | ✅ модель MXFP4, медленно |
| Генерация изображений | ✅ до 1024×1024 | ✅ до 1536×1024 | ✅ до 1536×1024 | ⚠️ разрешение уменьшено вдвое |
| Редактирование изображений | ✅ до 768 px | ✅ до 1024 px | ✅ до 1024 px | ⚠️ разрешение уменьшено вдвое |
| Генерация видео | ⚠️ 512×512×120 | ✅ 768×512×240 | ✅ 768×512×240 | ⚠️ адаптивное понижение |
| Голос (Whisper + TTS) | ✅ CPU | ✅ CPU | ✅ CPU | ✅ CPU |
| Поиск по документам (Qdrant) | ✅ | ✅ | ✅ | ✅ |
| Долговременная память (SLM) | ✅ CPU | ✅ CPU | ✅ CPU | ✅ CPU |

Измеренная производительность стартового стека и каждой кандидатной модели: [BENCHMARKS-ru.md](docs/BENCHMARKS-ru.md).

### Программные требования

- Сервер Linux, Docker Engine ≥ 20.10, Docker Compose ≥ 2.0
- **Режим GPU:** драйверы NVIDIA + NVIDIA Container Toolkit, GPU с 8 ГБ+ VRAM
- **Режим только CPU:** обычный Docker, без инструментов NVIDIA
- Один раз доступ в интернет для загрузки моделей — после этого ПЛИИ работает полностью офлайн

### Совместимость драйверов CUDA

`deploy.sh` читает драйвер хоста и выбирает подходящие образы. **Минимальный поддерживаемый драйвер: CUDA 12.2.**

| Драйвер хоста | Образы | Примечания |
|-------------|--------|-------|
| ≥ 13.0 | CUDA 13.0.1 + `llama-swap:v255-cuda13-b10991` | Стандартно |
| 12.8 – 12.9 | CUDA 12.8.1 (Ubuntu 24.04) | Стандартно |
| 12.6 – 12.7 | CUDA 12.6.3 (Ubuntu 24.04) | Требования к образу сняты |
| 12.4 – 12.5 | CUDA 12.4.1 (Ubuntu 22.04) | Требования к образу сняты |
| **12.2 – 12.3 (минимум)** | CUDA 12.2.2 (Ubuntu 22.04) | Требования к образу сняты для всех GPU-сервисов |

llama-swap зафиксирован намеренно: в upstream в версии 243 изменился формат конфигурации, и плавающий тег ломает свежие развёртывания. Ниже 12.2 скрипт отказывается от режима GPU и переходит на режим только CPU.

Проблемы развёртывания: [TROUBLESHOOTING-ru.md](docs/TROUBLESHOOTING-ru.md) · подробности авто-подбора: [VRAM_MANAGEMENT-ru.md](docs/VRAM_MANAGEMENT-ru.md).

## 🚀 Быстрый старт

> 💡 Для развёртывания на GPU нужны **драйверы NVIDIA** и **NVIDIA Container Toolkit**.

### Вариант A — автоматический (рекомендуется)

Один скрипт создаёт `.env` с безопасными секретами, скачивает модели, собирает образы и запускает всё.

```bash
git clone https://github.com/barval/flai.git
cd flai

# Ядро: чат, зрение, рассуждения, вызов инструментов
./deploy.sh --download-models

# + генерация и редактирование изображений
./deploy.sh --download-models --with-image-gen

# + голос — выберите ОДИН бэкенд (Piper по умолчанию, --with-voice — алиас)
./deploy.sh --download-models --with-image-gen --with-voice-piper
./deploy.sh --download-models --with-image-gen --with-voice-kokoro

# + поиск по документам (Qdrant)
./deploy.sh --download-models --with-image-gen --with-voice-piper --with-rag

# + генерация видео (LTX-Video)
./deploy.sh --download-models --with-image-gen --with-voice-piper --with-rag --with-video

# + долговременная память, + веб-поиск, + краулер сайтов
./deploy.sh --download-models --with-image-gen --with-voice-piper --with-rag \
  --with-video --with-slm --with-search --with-crawler

# Прогнать набор тестов после развёртывания
./deploy.sh --download-models --with-image-gen --run-tests
```

Нет NVIDIA GPU? Добавьте `--cpu`; тогда автоматически выбирается `docker-compose.cpu.yml`. Переключение между GPU и CPU не требует пересборки — образы помечены по бэкенду и сосуществуют локально.

### Вариант B — ручной

```bash
git clone https://github.com/barval/flai.git
cd flai

sudo mkdir -p data data/uploads data/documents
sudo chown -R 1000:1000 data
cp .env.example .env
```

Сгенерируйте два секрета и задайте часовой пояс, URL и настройки:

```bash
sed -i "s|^SECRET_KEY=.*|SECRET_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")|" .env
sed -i "s|^QDRANT_API_KEY=.*|QDRANT_API_KEY=$(python3 -c "import secrets; print(secrets.token_hex(32))")|" .env
nano .env
```

Скачайте модели в `services/*/models/`. Полный список файлов, размеров, лицензий и команд `wget` — в [MODELS-ru.md](docs/MODELS-ru.md); Model Hub в админ-панели может скачать их за вас с прогрессом и докачкой.

Запустите сервисы — каждый профиль опционален:

```bash
# Чат, зрение, рассуждения, инструменты (базовый стек)
docker compose -f docker-compose.gpu.yml up -d

# Добавить подсистемы
docker compose -f docker-compose.gpu.yml \
  --profile with-image-gen --profile with-voice-piper --profile with-rag \
  --profile with-video --profile with-slm --profile with-search --profile with-crawler up -d

# Хосты только на CPU используют другой файл compose
docker compose -f docker-compose.cpu.yml up -d
```

> ⏱️ Первая сборка компилирует stable-diffusion.cpp из исходников и занимает время; последующие сборки используют кэш.

Задайте пароль администратора и откройте инстанс:

```bash
docker exec flai-web flask admin-password YourSecurePassword123
```

Затем войдите как `admin` по адресу `http://localhost:5000`:

1. **Админ-панель → Модели** — подтвердите мультимодальную модель, модель рассуждений и модель эмбеддингов; при необходимости поправьте параметры. Контекстное окно, не помещающееся в бюджет ОЗУ/VRAM, отклоняется при сохранении, а фоновая dry-load откатывает конфигурацию, если загрузка не удалась.
2. **Админ-панель → Пользователи** — создайте учётные записи и назначьте классы сервисов и права на камеры.
3. **Отправьте первое сообщение** — роутер сам выберет подсистему. Прикрепите документ, изображение или голосовое сообщение, чтобы увидеть другие сценарии.

### Всё настраивается переменными окружения

У каждого сервиса есть профиль, а большинство настроек живёт в `.env`: профили compose, таймауты, лимиты VRAM и памяти, URL моделей, поисковые ключи, настройки Tavily и краулера, лимиты частоты запросов API, брендинг. Многие runtime-настройки (модели, пользователи, бэкапы, брендинг, камеры) управляются через админ-панель. Полный справочник со значениями по умолчанию — в [CONFIGURATION-ru.md](docs/CONFIGURATION-ru.md).
