# Администрирование

## Для чего нужна панель администратора

- 👤 **Управление пользователями** – добавление, редактирование, удаление пользователей; смена паролей; назначение классов обслуживания
- 🔑 **Права доступа к камерам** – контроль доступа пользователей к камерам (опционально)
- 🤖 **Управление моделями** – выбор и настройка GGUF-моделей для мультимодальности, рассуждений и эмбеддинга прямо из панели администратора
- 🧭 **Model Hub** – поиск GGUF-моделей на Hugging Face с оценкой совместимости с GPU/RAM до скачивания, скачивание с прогрессом/докачкой, удаление скачанных файлов и работа в оффлайн-режиме
- 💾 **Резервное копирование и восстановление** – создание и восстановление полных или «только пользователи» резервных копий прямо из веб-интерфейса
- 🎨 **Персонализация** – брендирование экземпляра:
  - **Логотип в шапке** – загрузка кастомного логотипа (PNG/JPEG/WebP, автоматическое масштабирование до 128 px с сохранением прозрачности); при удалении возвращается встроенный логотип.
  - **Названия сайта** – на русском и английском (оба обязательны, не более 40 символов каждый); показываются в шапке, в заголовке вкладки браузера и в экспортированных чатах, на узких экранах шрифт уменьшается автоматически.
  - **Экспорт чатов** – повторяет футер живого сайта: короткая строка бренда открывает окно «О системе» (полное название, версия, ссылка на GitHub, копирайт), а кастомный логотип встраивается и в шапку, и в это окно.
  - **Резервные копии** – сохранённые настройки брендинга входят в полные резервные копии.
- 🖥 **Обзор оборудования** – первая вкладка для администратора: платформа (`nvidia`/`amd`/`intel`/`cpu`), название GPU, объём VRAM и RAM (доступно из всего), количество ядер CPU
- 📈 **Мониторинг системы** – просмотр размеров БД и системной статистики
- 🔧 **CLI-инструменты** – смена пароля администратора, очистка загрузок, миграция формата сообщений, импорт/очистка истории SLM, сброс чекпоинтов через Flask CLI

## Управление пользователями

### Возможности панели администратора

| Возможность | Описание |
|---------|-------------|
| 👤 Операции с пользователями | Создание, редактирование, удаление учётных записей |
| 🔑 Управление паролями | Сброс пароля любому пользователю |
| 🔐 Права на камеры | Выдача/отзыв доступа к камерам для каждого пользователя |
| 🔢 Токены по пользователям | Просмотр и сортировка отправленных входных и полученных выходных токенов |
| 🤖 Управление моделями | Настройка GGUF-моделей по типам модулей |
| 📊 Системная статистика | Мониторинг размеров БД и хранилища |
| 🎚️ Классы обслуживания | Настройка приоритета очереди (0 — высший, 2 — низший) |
| 📋 Счётчик задач | В таблице пользователей показано число фоновых задач каждого пользователя (колонка «Задачи», после «Сессий»); внутренние классы задач (3/4/5) администраторам не предлагаются — классы обслуживания остаются 0/1/2 |
| 💾 Хранилище | В таблице пользователей колонка «Хранилище» перед «Сессиями» показывает занятое место / лимит пользователя, сортируется численно; лимит редактируется прямо в ячейке (в МБ), пустое поле возвращает общий `MAX_UPLOAD_STORAGE_MB`; превышение квоты подсвечивается. Колонки разделены пунктирными линиями. Строка системной статистики сопоставляет старые подписи «База пользователей»/«База чатов» с реальными размерами таблиц PostgreSQL |

## CLI-команды

```bash
# Смена пароля администратора
docker exec flai-web flask admin-password NewPassword123

# Справка по командам
docker exec flai-web flask --help
```

## 💾 Резервное копирование и восстановление

ПЛИИ имеет встроенную систему резервных копий, доступную во вкладке **«Резервные копии»** панели администратора.

**Типы резервных копий:**
- **Только пользователи:** резервная копия только таблицы `users` (учётные записи, права доступа, настройки). История чатов и счётчики токенов не копируются.
- **Полный:** резервная копия всех данных: пользователи, сессии чатов, сообщения (включая счётчики входных/выходных токенов), документы, загруженные файлы, конфигурация моделей.

**Операции:**
- **Создать:** выберите тип резервной копии и нажмите «Создать резервную копию». Архив сохраняется в `data/db_backups/`.
- **Восстановить:** нажмите «Восстановить» у нужного архива — текущее состояние БД и файлов будет заменено содержимым резервной копии. *Внимание: восстановление перезаписывает существующие данные.*
- **Скачать:** загрузка архива резервной копии на локальный компьютер.
- **Удалить:** удаление старых архивов.

Файлы резервных копий хранятся в виде `.tar.gz` с SQL-дампом и директориями с файлами. Восстановление требует подтверждения и фиксируется в аудит-логе.
