# Интеграция камер

Модуль камер подключается к отдельному сервису `room-snapshot-api`. Подробные инструкции по развёртыванию см. в [../services/README.md](../services/README.md) и [services/room-snapshot-api/README.md](../services/room-snapshot-api/README.md).

## Управление камерами (панель администратора)

В панели администратора есть вкладка **«Камеры»** с полным набором CRUD-операций:
- **Синхронизация** – импорт списка камер из room-snapshot-api (эндпоинт `/rooms`)
- **Включить/Отключить** – по отдельности для каждой камеры
- **Предпросмотр миниатюр** – снимки с камер загружаются лениво с кэшированием в localStorage
- **Распознавание русских названий** – морфологический анализ через pymorphy3 формирует все грамматические склонения (именительный, винительный, предложный падежи) для каждого названия помещения. Благодаря этому ИИ правильно понимает фразы: «покажи гостиную», «что в гостиной», «на кухне» и т.п.

Данные о комнатах с камерами хранятся в таблице базы данных `camera_rooms` (поля: code, name_forms, enabled, sort_order).

## Конфигурация
```bash
CAMERA_API_URL=http://flai-room-snapshot-api:5000
CAMERA_ENABLED=true
CAMERA_API_TIMEOUT=15
CAMERA_CHECK_INTERVAL=30
```

## room-snapshot-api v1.3

Сервис аутентифицирует каждый эндпоинт общим ключом и отдаёт один и тот же набор
камер по REST и через MCP. FLAI передаёт ключ в каждом запросе, просит свой язык и
переиспользует кэш снимков сервиса.

| Настройка | Смысл |
|---|---|
| `CAMERA_API_KEY` | Общий ключ для REST и MCP (`X-API-Key`). Пустое значение — сервис без аутентификации, допустимо только в приватной сети. |
| `CAMERA_MCP_URL` | MCP-эндпоинт streamable HTTP (`http://host:5006/mcp`) — задел под агентный режим. |
| `CAMERA_SNAPSHOT_WIDTH` | Ширина превью (по умолчанию 384 px); сервис масштабирует до захвата. |
| `CAMERA_PREVIEW_WORKERS` | Сколько камер захватывается параллельно за одно обновление (по умолчанию 4). |

**Язык.** По умолчанию сервис отдаёт английские названия комнат, поэтому FLAI
передаёт `Accept-Language` (и `?lang=`) вместе с языком интерфейса. Русская
установка сохраняет русские названия без отдельного файла переводов.

**Обновление превью.** `GET /admin/api/cameras/previews` снимает все включённые
камеры одним запросом: модуль раздаёт их через пул потоков с ограничением, сервис
захватывает параллельно, ответ несёт каждое превью как data URL. Один круг вместо
запроса на строку — раньше браузер сериализовал их своим лимитом соединений, пока
ffmpeg на той стороне работал последовательно.

**Кэширование.** Снимки несут `ETag`/`Cache-Control`. Прокси
`/admin/api/cameras/<code>/proxy` передаёт `If-None-Match` и отвечает `304 Not
Modified`, не трогая камеру, поэтому повторное открытие вкладки не переснимает
кадры.

**Здоровье.** `/health` всегда отвечает HTTP 200 и сообщает
`healthy`/`degraded`/`unhealthy` с доступностью каждой камеры. Вкладка «Камеры»
показывает число онлайн-камер рядом с кнопкой синхронизации.

**MCP (агентный режим).** `GET /admin/api/cameras/mcp` подключается к MCP-серверу
(JSON-RPC поверх streamable HTTP, ответы JSON или SSE), перечисляет инструменты
(`list_rooms`, `get_snapshot`, `room_info`, `health`) и сообщает доступность. В
чат этот путь пока не встроен: модуль `modules/cam_mcp.py` — та поверхность
инструментов, которую будет вызывать агентный слой вместо работы с RTSP и
собственного проксирования снимков.

## Права доступа к камерам
В Панель администратора → вкладка Пользователи можно назначить коды камер:
`tam` (тамбур/вход), `pri` (прихожая), `kor` (коридор), `spa` (спальня),
`kab` (кабинет), `det` (детская), `gos` (гостиная), `kuh` (кухня), `bal` (балкон)
