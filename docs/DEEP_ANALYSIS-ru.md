# Режим глубокого анализа (RLM)

Модель по ходу дела использует три инструмента (плюс `final`), и все они объявлены в общем манифесте (`app/tool_registry.py:RLM_TOOL_SPECS`, `exec="sandbox"`), поэтому поверхность песочницы имеет одно место:

| Инструмент | Что делает |
|------|--------------|
| 🐍 `python` | выполняет код в изолированной песочнице — разбирает тексты, считает слова, извлекает абзацы, ищет по шаблону, анализирует таблицы, производит расчёты |
| 🤖 `llm` | делает точечный подзапрос вспомогательной модели (ограниченное количество токенов), затем включает результат в основное рассуждение |
| 🌐 `web_fetch` | ищет свежую информацию в интернете (SearXNG), если она нужна для ответа — модель стимулируется использовать не более 2 поисков (жёсткий максимум — 5) |

Всё работает **локально** как одна задача: модель рассуждений остаётся загруженной на всё время анализа, прогресс транслируется в реальном времени («Читаю документы...», «Шаг анализа N...»), а результат выводится с разворачиваемой сводкой **«Глубокий анализ (N шагов)»**.

Ответ всегда выдаётся на выбранном вами языке. Кроме того, модель обязана реально проработать выбранные файлы: вызов `final(answer)` до того, как инструмент `python` хотя бы раз проанализировал корпус документов, отклоняется с корректирующей инструкцией (для корпуса из нескольких файлов). Системный промпт запрещает давать ответ до изучения всех файлов корпуса — поэтому при вопросе по двум договорам (например, по квартире) ответ не будет ограничиваться только первым, пропустив второй.

**Как пользоваться:**
1. Загрузите файлы для анализа в раздел **«Документы»** (PDF, DOC, DOCX, MD, HTML, ODT, RTF, TXT, CSV, JSON, EPUB, XLSX, XLS, PPTX, FB2, XML, YAML, TOML, INI, LOG, EML и изображения).
2. В панели **«Документы»** отметьте нужные документы чекбоксами. Это единый корпус для чата (RAG), глубокого анализа и задач: чек-бокс папки отмечает все документы внутри, **«Без папки»** — документы в корне. Переключатель 🔬 меняет только инструмент — он не сбрасывает выбор, и те же отмеченные документы ограничивают обычные вопросы и задачи.
3. Напишите вопрос, включите переключатель **🔬 Глубокий анализ** и нажмите **Отправить**.
4. *(Необязательно)* Прикрепите до 4 изображений: мультимодальная модель составит подробное текстовое описание каждого, и каждое описание станет ещё одним «документом» для анализа — можно, например, спросить: «Сопоставьте приложенные фото гарантийного талона с пунктом 4 договора». Документы, приложенные прямо к сообщению чата, тоже попадают в корпус, поэтому выбор в панели «Документы» при наличии вложений не обязателен.
5. Наблюдайте за стадиями прогресса; когда появится сводка трассировки, разверните её, чтобы увидеть, как модель пришла к ответу.

## Примечания
- Если не выбраны ни документы, **ни** вложения (изображения или документ, приложенный к чату), отправка отклоняется с локализованным сообщением, а переключатель остаётся включённым — глубокий анализ никогда не превращается в обычный чат молча. Изображение без вопроса отклоняет и сам эндпоинт.
- Анализ проводится только по корпусу: отмеченные документы, а для задачи с включённым 🔬 и без вложений — по всем проиндексированным документам пользователя (когда корпус отмечен, поиска по посторонним загрузкам нет).
- В песочнице уже доступны `re` и `math` — актор не пишет `import` и не использует `lambda` (вместо неё обычные функции/циклы). Отказавший вызов python нужно исправить на следующем шаге; повторение того же отказавшего кода тратит лимит шагов.
- На последнем шаге доступен только инструмент `final`, а вызовы инструментов, напечатанные обычным текстом (вместо структурного формата), распарсиваются обратно и исполняются — включая незакрытую форму `<tool_call><function=final> answer="…"`; если модель повторила уже напечатанный ответ утёкшим `final`, побеждает полная напечатанная копия, а разметка отрезается. Анализ никогда не отвечает пользователю внутренним диалогом модели.
- Чтобы остановить анализ, нажмите **Отмена** — проверка отмены выполняется на каждом шаге.
