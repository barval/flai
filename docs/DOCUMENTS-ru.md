# Документы и RAG

## Лимиты загрузки

| Что | Лимит | Переменная |
|------|-------|----------|
| Один документ | 25 МБ | `MAX_DOCUMENT_SIZE_MB` |
| Документов на пользователя | 250 | `MAX_DOCUMENTS_PER_USER` |
| Хранилище документов на пользователя | 250 МБ | `MAX_DOCUMENTS_STORAGE_MB` |
| Папок на пользователя | 250 (как лимит документов) | `MAX_DOCUMENTS_PER_USER` |
| Бюджет OCR сканированных PDF | 30 минут на документ | `OCR_TIME_BUDGET_S` (0 = без ограничения) |

Когда бюджет OCR исчерпан, уже распознанные страницы индексируются, и пользователь получает уведомление, до какой страницы дошло распознавание.

## 1. Настройка RAG в панели администратора

После запуска сервисов войдите как администратор и откройте **Панель администратора → вкладка «Модели»**. Прокрутите вниз до раздела **«Фрагментация (Chunks)»**. Здесь можно тонко настроить поведение RAG:

- **Размер фрагмента (символы):** как документы разбиваются на части для индексации.
- **Перекрытие фрагментов (символы):** количество символов, общих для соседних фрагментов.
- **Стратегия фрагментации:** `fixed` (по количеству символов), `recursive` (по заголовкам/абзацам) или `structured` (одна логическая запись на фрагмент — см. [Стратегии нарезки](#стратегии-нарезки)).
- **Количество фрагментов (top_k):** максимальное число фрагментов, извлекаемых из Qdrant по запросу.
- **Порог (документы):** минимальный балл похожести для обычного поиска по документам.
- **Порог (рассуждения):** минимальный балл похожести, когда RAG срабатывает из запроса модели рассуждений.

Нажмите **Сохранить**, чтобы применить изменения. Если изменить параметры фрагментации (размер или стратегию), автоматически запустится фоновая переиндексация всех документов.

> **Примечание:** переменные окружения вроде `RAG_CHUNK_SIZE` в `.env` используются только как начальные значения до первого сохранения настроек. Основная конфигурация хранится в базе данных.

## 2. Включение в Docker Compose

```bash
docker compose -f docker-compose.gpu.yml --profile with-rag up -d
```

## 3. Загрузка документов

1. Войдите в веб-интерфейс
2. Нажмите вкладку **«Документы»** в боковом меню
3. Нажмите ➕ и загрузите файлы в форматах PDF, DOC, DOCX, TXT, ODT, RTF, CSV, JSON или EPUB
4. Дождитесь окончания индексации (статус: ✅ Проиндексирован)

## 4. Поиск по документам в чате

После индексации документов поиск по ним происходит автоматически:

1. Убедитесь, что документы есть в панели **«Документы»** со статусом **✅ Проиндексирован**.
2. Задайте любой вопрос в чате. Когда ответу требуются ваши документы, ассистент вызовет инструмент 📚 `rag_search` и в реальном времени покажет **«📚 Ищу в документах...»**, затем встроит извлечённые фрагменты в ответ (извлечение RAG выполняется на быстром воркере; обоснованный ответ формирует модель рассуждений). Извлечение **защищено от потери файлов**: если какой-либо из ваших проиндексированных документов не попал в топ по семантике, его лучший фрагмент всё равно будет передан модели рассуждений — ответ не потеряет целый договор только из-за низкого балла похожести.
3. RAG работает **по пользователю и по запросу**: поиск идёт только по документам текущего пользователя, а маршрутизатор LLM сам решает, нужна ли для ответа документация.

Для глубокой многошаговой работы по набору документов — сравнения, подсчёты, структурные отчёты, поиск всех исключений — лучше использовать переключатель 🔬 **Глубокий анализ** (см. [Режим глубокого анализа](DEEP_ANALYSIS-ru.md)).

## Реранкинг

Поиск решает, какие фрагменты вообще рассматривать; кросс-энкодер решает, в каком порядке: он читает
запрос и фрагмент вместе. `bge-reranker-v2-m3` (Q4_K_M, ~0,42 ГБ) работает как **CPU-only**
llama-server, зарегистрированный конфигом llama-swap: он не занимает GPU-слот, и поиск никогда не ждёт
чат. Группа `cpu_only` объявлена с `exclusive: false` и `persistent: true` — иначе реранкер и модель
эмбеддингов выгружают друг друга, и каждый запрос платит две загрузки (3,5 с вместо 0,15 с).

Включается через `RAG_RERANK_ENABLED=true` (по умолчанию выключен — см. замеры ниже);
`RAG_RERANK_CANDIDATES` (по умолчанию 10) задаёт, сколько верхних кандидатов переупорядочивать.
Эндпоинт отдаёт сырые логиты, поэтому `app/reranker.py` прогоняет их через сигмоиду и масштабирует по
лучшему кандидату только для порядка; сам поиск сохраняет косинусную оценку каждого фрагмента.
Абсолютный порог релевантности, применённый к относительной шкале, сжимал 20-фрагментный контекст до
двух верхних, и ответ терял почти все записи.

Замеры на том же наборе из 22 вопросов: в узком 5-фрагментном окне (инструмент `rag_search`, который
используют глубокий анализ и задачи) он помогает (nDCG 0.815 → 0.831, MRR 0.723 → 0.750), но в
20-фрагментных окнах чата и задач при включённом гибриде снижает nDCG (0.965 → 0.922) и стоит ~280 мс
на поиск. Поэтому по умолчанию он выключен и включается под конкретную установку, где меньшее окно —
единственный потребитель.

Загрузка (опционально):

```bash
curl -L -o models/bge-reranker-v2-m3-Q4_K_M.gguf \
  https://huggingface.co/gpustack/bge-reranker-v2-m3-GGUF/resolve/main/bge-reranker-v2-m3-Q4_K_M.gguf
```

## Стратегии нарезки

В админ-панели → «Модели» → «Chunks» доступны три стратегии:

| Стратегия | Поведение |
|---|---|
| `fixed` | Окна по символам с перекрытием; дешевле всего, режет по середине предложения |
| `recursive` | Делит по абзацам, предложениям и словам; предложения остаются целыми |
| `structured` | Делит по логическим записям: запись с датой (начало, организация, город) или блок с датой остаётся одним фрагментом, включая строку с датой окончания и городом; блок больше размера фрагмента уходит в рекурсивную нарезку |

`structured` нужна для вопросов-подсчётов («сколько мест работы в этом городе»): когда две записи
попадают в один фрагмент, модель считает внутри фрагмента и обычно ошибается. Замер записан в
CHANGELOG к гибридному поиску — поиск перестал быть узким местом, узким местом стала нарезка.

Смена стратегии применяется при следующей индексации. Переиндексировать существующие документы:
`flask rag-reindex --user <login>` (или `--doc <id>`); старые точки удаляются заранее, поэтому
осиротевших фрагментов не остаётся.

## Область поиска

В чате можно указать, **по каким документам** разрешено отвечать. Область задаётся рядом с полем ввода
(🔍): папка и диапазон дат загрузки (обе границы включительно), комбинируются через И. Если ничего не
задано — поиск глобальный, как раньше.

- **Разрешение.** Область превращается в список document id в PostgreSQL до постановки в очередь,
  поэтому повторная постановка задачи сохраняет область, перенос документа между папками действует
  сразу, а переиндексация не требуется.
- **Изоляция.** Поиск не видит документы вне области. **Пустое** совпадение — это честный ответ:
  поиск ничего не возвращает, и модель говорит, что в выбранных документах данных нет, вместо того
  чтобы молча отвечать по остальному корпусу.
- **Вложения.** Документ, прикреплённый к сообщению, всегда попадает в контекст; область сужает только
  остальной поиск.
- **Покрытие.** Проход покрытия файлов (гарантия, что каждый проиндексированный документ получит место
  в контексте) ограничивается той же областью.
- **Период** — дата загрузки, а не дата внутри документа.
- **API.** `POST /api/send_message` принимает `filter_folder`, `filter_from`, `filter_to` (multipart
  или JSON). Публичный `/v1` область пока не поддерживает.

## Гибридный поиск

По умолчанию поиск плотный: запрос превращается в вектор, Qdrant отдаёт ближайшие фрагменты. Это
промахивается на запросах с редким словом — «сколько мест работы в этом городе» ставит болтовню из
чата про этот город выше резюме, потому что вектор размывает единственный важный терм.

С `RAG_HYBRID_ENABLED=true` каждый фрагмент дополнительно зеркалируется в PostgreSQL (`rag_chunks`,
генерируемый `tsvector` с русской морфологией) и работают оба поисковика: Qdrant по смыслу, PostgreSQL
по термам. Два ранжированных списка сливаются через **reciprocal rank fusion** (`RAG_RRF_K`, по
умолчанию 60): фрагмент, который нашли оба, оказывается выше того, что нашёл только один. Термы
выбираются аккуратно:

- дискриминативные — имена собственные и слова латиницей (города, компании, названия инструментов);
- термы, встречающиеся в большой доле корпуса, отбрасываются (у `ts_rank_cd` нет IDF, иначе имя,
  которое есть в половине фрагментов, перебьёт город, встречающийся пять раз);
- совпадение идёт по префиксу: русский стеммер может дать для именительного и предложного падежа
  одного и того же названия разные лексемы;
- фрагмент из документа, чьё **название** совпадает с запросом, получает бонус — резюме названо по
  имени человека, экспорт чата — нет.

Уже загруженные документы зеркалируются командой `flask rag-backfill-chunks --user <login>`; новые
загрузки зеркалируются автоматически и удаляются вместе с векторами. Настройки: `RAG_HYBRID_ENABLED`,
`RAG_HYBRID_CANDIDATES` (пул кандидатов от каждого поисковика, по умолчанию 30), `RAG_RRF_K`; все три
есть и в админ-панели → «Настройки». Перед включением измерьте эффект по `docs/RAG_EVAL-ru.md`.

## 5. Документы, приложенные к чату

Документ можно приложить прямо к сообщению чата (та же кнопка 📎; PDF/DOC/DOCX/TXT/ODT/RTF/CSV/JSON/EPUB до `MAX_DOCUMENT_SIZE_MB`). Он сохраняется как полноценный документ пользователя, индексируется обычным конвейером (извлечение текста; отсканированные PDF проходят постраничный OCR в рамках `OCR_TIME_BUDGET_S`, а при исчерпании бюджета сохраняется уведомление о частичном распознавании), и вопрос по нему решается через RAG — без ручного шага через панель «Документы». Проиндексированный документ появляется в панели и учитывается в пользовательской квоте; изображения могут сопровождать его в том же сообщении и служить визуальным контекстом.

Вложения чата (изображения и приложенный документ) хранятся на диске в папке загрузок сеанса; их пути записаны в записи сообщения, поэтому каждая картинка остаётся видимой после перезагрузки страницы. Удаление сеанса стирает все файлы, на которые ссылаются его сообщения, — включая каждое приложенное изображение, а не только первое, — и вычитает их размеры из квоты хранилища пользователя. Команда `flask cleanup-uploads` собирает ссылки из тех же двух источников, поэтому никогда не удаляет файлы живых сеансов, а после удаления сирот пересчитывает счётчик `user_storage` каждого пользователя по реально оставшимся файлам (счётчик, который не уменьшался вне удаления сеанса, мог держать пустой аккаунт за пределами квоты).

## 6. Организация документов по папкам

Одноуровневые папки (без вложений) помогают навести порядок в панели «Документы».

- **Создание** — кнопка 📁 над списком открывает отдельное окно ввода имени папки (нативный `prompt()` не используется): введите название (до 64 символов, дубликаты отклоняются), подтвердите кнопкой **Создать** или Enter, закройте с помощью **Отмена**/Esc/✕; дублирующиеся или некорректные имена показывают встроенную ошибку под полем. **Переименование** — ✏️ на папке открывает то же окно с заранее заполненным полем. **Удаление** — 🗑️ спрашивает дважды: сначала простое подтверждение, затем второе — «вместе с папкой будет удалено N документов (ОБЪЁМ)» — каскад удаляет записи RAG, файлы на диске и строки БД и освобождает квоту точно так же, как последовательное удаление документов поодиночке.
- **Сворачивание/разворачивание** — клик по заголовку папки (📂 развёрнута / 📁 свёрнута); состояние запоминается для пользователя в `localStorage`.
- **Перемещение** — кнопка 📂 на документе открывает меню (корень и все папки) и работает на мобильных; на десктопе документ можно также перетащить на заголовок папки.
- **Загрузка в папку** — если папки есть, ➕ показывает меню выбора цели (корень или папка); иначе загрузка идёт в корень, как раньше.
- **Групповые операции** — у каждого документа есть флажок; флажки папок имеют три состояния (все/частично/ничего). Плашка появляется, когда что-то отмечено, и показывает «Выделено N · ОБЪЁМ» с тремя кнопками: **➤ 📂** (переместить в папку — скрыта, пока включён переключатель «Глубокий анализ»), **✖** (снять выделение) и **🗑️** (удалить выбранные документы — подтверждение «Вы хотите удалить N выбранных документов на ОБЪЁМ?», затем удаление по одному через тот же конвейер, что и одиночное, и перезагрузка списка).
- **Единый набор выделения для перемещения и глубокого анализа** — чекбоксы — единственный способ выбрать документы. При включённом переключателе 🔬 отметка документа включает его в корпус анализа (зелёная рамка + галочка); при выключенном переключателе те же чекбоксы управляют плашкой перемещения. Выбор зеркалируется в набор анализа в обоих режимах, поэтому снятие флажка с папки убирает и зелёную подсветку её документов; снятие переключателя мгновенно сбрасывает корпус, а повторное включение заново строит его из текущих чекбоксов.

API: `GET /api/documents` теперь возвращает `{folders, documents}`, где каждая папка несёт `id`, `name`, `created_at`, `count` и `size`; `POST /api/document-folders` (создание), `PATCH /api/document-folders/<id>` (переименование), `DELETE /api/document-folders/<id>` (каскад, возвращает `deleted_documents`/`deleted_size`), `PATCH /api/documents/<doc_id>/folder` (перемещение одного; `folder_id: null` перемещает в корень) и `POST /api/documents/move` (`{doc_ids, folder_id}`) для группового перемещения. Загрузка документов принимает необязательное поле формы `folder_id` с проверкой владения.

## 7. Предпросмотр документа

Щёлкните по карточке документа на вкладке «Документы» — он откроется в основном окне (окно чата/задачи переключается в режим предпросмотра только для чтения). Заголовок показывает «Предпросмотр: <имя файла>» (длинное имя обрезается многоточием) в том же стиле, что заголовки чата и задач; счётчик «Сообщения» скрыт, а единственное действие — 💾 **Сохранить**, которое скачивает оригинал с его текущим именем. Переключение на другую вкладку (или Esc) возвращает окно чата/задачи.

- **PDF и изображения** отдаются inline (`/api/documents/<id>/preview/file`) и показываются браузером (`<iframe>` / `<img>`). На телефонах (≤ 768 px) PDF-iframe заменяется **отрисованными на сервере страницами** (`pdftoppm` → JPEG, `/api/documents/<id>/preview/pdf-page/<n>`, первые `PREVIEW_PDF_MAX_PAGES` = 30 страниц, с заметкой «Показаны первые N страниц») и ссылкой «Открыть PDF» — Chrome для Android не умеет показывать PDF внутри iframe и выводит «Этот контент заблокирован».
- **Простой текст** (`.txt`, `.md`, `.csv`, `.json`) показывается как есть.
- **DOCX, ODT, RTF, EPUB** преобразуются в текст (`extract_text_from_file`) и помечаются **«Извлечённый текст»** — исходное форматирование не воспроизводится.
- Для формата без предпросмотра выводится локализованная заметка «Предпросмотр для этого формата недоступен». Текстовые предпросмотры ограничены 200 000 символами с заметкой «Предпросмотр обрезан».

Все эндпоинты предпросмотра проверяют владельца и используют ту же проверку `realpath`, что и маршрут скачивания; inline отдаются только PDF и изображения (никогда HTML).
