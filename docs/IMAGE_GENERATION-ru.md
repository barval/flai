# Генерация и редактирование изображений

## Модель для генерации

Для генерации изображений в проекте используется только **Z_image_turbo**:

| Модель | Шагов | CFG Scale | Разрешение | Примечания |
|-------|-------|-----------|------------|-------|
| **Z_image_turbo** | 10 | 1.0 | до 1536×1536 | Быстрая, flow-matching |

Все загружаемые изображения автоматически уменьшаются до максимальной стороны **1536px** (настраивается через `MAX_IMAGE_SIZE` в `.env`), чтобы избежать переполнения контекста Qwen3VL и сократить объём дискового пространства.

Выбор модели настраивается через `SD_MODEL_TYPE` в `.env`:
```bash
SD_MODEL_TYPE=z_image_turbo
```

**«Нарисуй что-то похожее» с референсами** — приложите изображения-примеры к запросу генерации (в чате или через `image_references` в `POST /v1/images/generations`). Каждый пример описывается мультимодальной моделью, описания добавляются в начало промпта SD как примеры для подражания («Примеры для подражания (нарисуй что-то похожее):»), а к описанию добавляется реальный формат примера — в шаблоне генерации формат из примера имеет приоритет над правилом «по объекту». Сама SD получает только текст.

Запрос в чате с приложенными картинками, например *«нарисуй что-то похожее»*, классифицируется мультимодальной моделью в отдельный вариант `[-IMAGE-]` (создать НОВОЕ похожее изображение, в отличие от `[-IMAGE-EDIT-]`), и оба обработчика сообщений с картинками направляют его напрямую в генерацию с приложенными примерами.

## Редактирование изображений (Flux.2 Klein 4B)

Загрузите изображение и попросите его изменить (например, *«сделай зрачки зелёными»*, *«убери второе солнце»*). Система работает так:
1. **Мультимодальная модель** (Qwen3VL) анализирует изображение и формирует промпт для редактирования
2. **Flux.2 Klein 4B** через stable-diffusion.cpp выполняет редактирование
3. Оригинальное изображение сохраняется, изменяются только запрошенные элементы

Для редактирования исходные изображения автоматически уменьшаются до максимальной стороны **1024px**, чтобы избежать OOM на GPU с 16 ГБ памяти. Если изображение уменьшено, в чате выводится уведомление с исходными и новыми размерами.

Редактирование использует отдельные файлы модели и работает независимо от генерации — между ними нет конфликта.

## Сборка stable-diffusion.cpp

Сервис `sd_cpp` **собирается из исходников** при первом запуске `docker compose up`:
1. Клонируется репозиторий `https://github.com/leejet/stable-diffusion.cpp`
2. Инициализируются git-сабмодули (`ggml`, `thirdparty/*`)
3. Компилируется с CUDA 13.0.1 (`cmake -DSD_CUDA=ON`) или без CUDA для CPU
4. Создаются бинарники `sd-server` и `sd-cli`

В каждом compose-файле собирается **собственный тегированный образ** через build-arg `SD_BACKEND` (см. `Dockerfile.sd_cpp`):
- `docker-compose.gpu.yml` → `flai-sd_cpp:cuda` (`SD_BACKEND=cuda`)
- `docker-compose.cpu.yml` → `flai-sd_cpp:cpu` (`SD_BACKEND=cpu`; поддерживается также вариант `vulkan`)

Поскольку теги разные, GPU- и CPU-образы могут существовать одновременно — переключение между режимами (GPU/CPU-only) не требует пересборки.

> ⏱️ **Первая сборка**: ~5–10 минут в зависимости от CPU. Последующие сборки используют кэш Docker.

## Конфигурация

```bash
# HTTP API sd-wrapper (порт 7861)
SD_WRAPPER_URL=http://flai-sd:7861
SD_CPP_TIMEOUT=900                  # таймаут генерации/редактирования (секунды)
SD_CPP_DEFAULT_WIDTH=1024
SD_CPP_DEFAULT_HEIGHT=1024
SD_CPP_DEFAULT_CFG_SCALE=1.0
SD_CPP_DEFAULT_STEPS=10
```
