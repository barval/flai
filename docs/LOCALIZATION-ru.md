Этот документ описывает систему локализации, использование Flask-Babel и правила перевода README. Читайте его, добавляя пользовательские строки или обновляя файлы README.

> **Примечание к v10.0:** Только обновление версии до v10.0 в заголовках `.po` и в строках футера. Новых ключей i18n нет — удалённая карточка чат-модели в админ-панели уже была непереведённой.

> **Примечание (v9.2):** Новых ключей i18n не добавлено. Только обновление версии до v9.2 в заголовках `.po` и в строках футера.

## Основные правила

- Все **комментарии в коде** и **сообщения журнала** должны быть на английском.
- Все **пользовательские сообщения** (UI, уведомления, ошибки) должны использовать выбранный язык пользователя (i18n).
- Всегда держите файлы перевода (`messages.po`) актуальными и полными.
- Для русского языка только три файла могут содержать русский текст: `deploy-ru.sh`, `README-ru.md` и `LICENSE-ru` (все прочие файлы репозитория — только на английском).
- **Каждая** пользовательская строка ОБЯЗАНА быть обёрнута в `_()` / `self._()` / `gettext()`. Сырой `str(e)` НИКОГДА не должен возвращаться пользователю.
- **При добавлении или изменении сообщений об ошибках** ВСЕГДА проверяйте, что соответствующие ключи перевода есть в обоих файлах: `translations/en/LC_MESSAGES/messages.po` и `translations/ru/LC_MESSAGES/messages.po`.

## Flask-Babel 4.0.0 — строки формата `_tr()`

**КРИТИЧНО**: `gettext()` в Flask-Babel использует `%`-форматирование (`string % variables`), а НЕ `str.format()`.

Передача kwargs вида `{status}` напрямую в `gettext()` молча возвращает неотформатированную строку.

### Правильный шаблон

Всегда вызывайте `gettext(key)` без kwargs, а затем применяйте `result.format(**kwargs)` вручную.

**Примеры**:
- `app/llamacpp_client.py:28`
- `app/mixins.py:9`

```python
# ❌ НЕПРАВИЛЬНО — молча возвращает неотформатированную строку
message = _tr("Error: {status}", status=status)

# ✅ ПРАВИЛЬНО
message = _tr("Error: {status}").format(status=status)
```

## Извлечение через pybabel
Всегда используйте флаги ключевых слов при извлечении, поскольку `_tr` — это кастомное ключевое слово, не распознаваемое по умолчанию.
`ApiImageRejectedError` и `ApiTaskError` в `app/api_bridge.py` несут msgid первым
аргументом, поэтому они тоже зарегистрированы как ключевые слова — иначе строки ошибок API никогда не попадут в каталоги:

```bash
pybabel extract -F babel.cfg -k _tr -k ApiImageRejectedError -k ApiTaskError -o translations/messages.pot .
pybabel update -i translations/messages.pot -d translations
pybabel compile -d translations  # after editing .po files
```

`pybabel update` заполняет новые записи догадками по fuzzy из похожих msgid. Всегда проверяйте новые
блоки `#, fuzzy` и заменяйте их настоящим переводом — неверная догадка хуже пустой строки,
потому что UI показывает её как готовый перевод.

## Система перевода (v9.0+)
Скомпилированные файлы `.mo` **отслеживаются в git** вместе с исходными `.po`, поэтому каждая свежая клонированная копия репозитория сразу содержит рабочие переводы (bind-mount `./translations:/app/translations` в `docker-compose.gpu.yml` перекрывает каталоги, запечённые в образ, которые тоже компилируются при сборке через `RUN pybabel compile -d translations` в Dockerfile). После правки файлов `.po` выполните `pybabel compile -d translations` на хосте и закоммитьте и `.po`, и `.mo`. `deploy.sh`/`deploy-ru.sh` обновляют каталоги автоматически во время развёртывания и громко предупреждают, если какой-либо каталог отсутствует. Все функции сайта работают и в русском, и в английском профиле.

## Префикс сообщений об ошибках
Все сообщения об ошибках, показываемые пользователю, ОБЯЗАНЫ начинаться с `"⚠️ "`.

`_build_error_response()` добавляет этот префикс автоматически. Однако строки ошибок из `call_llamacpp()` (например, `"GPU memory unavailable"`, `"HTTP error 500"`) возвращались как обычные строки через `process_reasoning()` и `rag.generate_answer()` — и попадали в `_save_and_respond()` без префикса `"⚠️ "`.

Исправление: добавлен вспомогательный `_is_llm_error_string()`, и обнаруженные ошибки направляются через `_build_error_response()` во всех затронутых участках кода:
  - `_process_reasoning_request`
  - `_process_text_task`
  - `_process_text_task_stream`
  - обработка ответов RAG в обоих `_process_text_task` и `_process_text_task_stream`

## Правила перевода README

### README.md (английский)

Разделы, которые нужно обновлять:

  1. **Список возможностей** (`### ✨ Features`) — добавить новые возможности, убрать устаревшие
  2. **Таблица «Что нового»** (`### What's New in vX.X`) — обновить номер версии и добавить новые возможности
  3. **Таблица основных компонентов** (`### Core Components`) — добавить/убрать сервисы, обновить порты
  4. **Уровни оборудования** (`### Hardware Tiers`) — обновить требования к VRAM/ОЗУ, если они изменились
  5. **Бенчмарки моделей** (`### Model Benchmarks`) — добавить новые модели, обновить данные о производительности
  6. **Команды быстрого старта** (`### Quick Start`) — обновить флаги deploy.sh, если изменились профили
  7. **Профили Docker Compose** — перечислить все доступные профили с описаниями
  8. **Раздел «Конфигурация»** — обновить переменные окружения, если они добавлены или изменены

Правила оформления:

  - Используйте таблицы для структурированных данных (компоненты, бенчмарки, тиры)
  - Используйте префиксы-эмодзи для списков возможностей (в соответствии с существующим стилем)
  - Держите описания краткими (1-2 строки на возможность)
  - Указывайте номер версии в заголовке «Что нового»: `### What's New in vX.X`

### README-ru.md (русский)

Правила перевода:

  - Переводите ВСЁ новое содержимое из README.md на русский
  - Оставляйте технические термины на английском (Docker, GPU, VRAM, llama.cpp и т. д.)
  - Оставляйте блоки кода и примеры команд на английском
  - Переводите заголовки разделов, описания возможностей и пояснительный текст
  - Поддерживайте идентичную структуру и форматирование с README.md

Разделы, которые ОБЯЗАНЫ быть переведены:

  - Список возможностей (все пункты)
  - Таблица «Что нового» (столбец Feature переведён, столбец Notes переведён)
  - Таблица основных компонентов (столбцы Component и Purpose переведены)
  - Уровни оборудования (столбец Feature переведён)
  - Инструкции быстрого старта (описания, а не команды)
  - Весь пояснительный текст и примечания

Разделы, которые остаются на английском:

  - Блоки кода (```bash ... ```)
  - Примеры команд (`./deploy.sh --download-models`)
  - Технические параметры (порты, имена моделей, пути к файлам)
  - Текст бейджей (уже на английском)
  - Ссылки на GitHub и URL
