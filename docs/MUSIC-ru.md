# Генерация музыки

FLAI умеет превращать текст песни и описание стиля в озвученную песню. Модель работает в
собственном контейнере (`flai-music`), потому что приносит свой стек PyTorch; веб-приложение
общается только с её REST API.

| Параметр | Значение |
|---|---|
| Модель | ACE-Step 1.5, `acestep-v15-turbo` (DiT 2B) + `acestep-5Hz-lm-0.6B` |
| Лицензия | MIT и на коде, и на весах |
| Образ | ~9 ГБ (CUDA runtime + torch); веса — том, ~11 ГБ при первом запуске |
| Включение | `./deploy.sh --with-music` или вручную `--profile with-music` |
| Настройки | `MUSIC_URL` (пусто — модуль выключен), `MUSIC_TIMEOUT_S`, `MUSIC_MODEL`, `MUSIC_LM_MODEL`, `MUSIC_DEFAULT_DURATION_S`, `MUSIC_MAX_DURATION_S` |

## Требования

| | Хост с GPU | Хост только с CPU |
|---|---|---|
| VRAM | минимум 8 ГБ (измеренный пик 6,9 ГБ), комфортно 16 ГБ | — |
| RAM | ~6 ГБ (веса выгружены) | **15 ГБ** по замеру |
| Диск | образ 20,8 ГБ + веса 11 ГБ | образ 11,8 ГБ + веса 11 ГБ |
| Образ | `flai-music:cuda` (`services/music/Dockerfile`) | `flai-music:cpu` (`Dockerfile.cpu`, колесо torch для CPU) |
| Скорость, песня 30 с | 12–15 с | 4–5 мин (~8× реального времени) |
| Включение | `./deploy.sh --with-music` | `MUSIC_ALLOW_CPU=1 ./deploy.sh --with-music` |

На хостах AMD и Intel нет CUDA-образа: они работают на CPU-стеке, где музыка — это
описанный ниже осознанный CPU-путь. Такое сочетание не измерялось.

Уровни 8–12 ГБ запускают пару 2B после вытеснения чат-модели с карты; контейнер музыки
освобождает VRAM по завершении песни, поэтому чат загружается на следующем сообщении. Уровень
XL 4B требует ≥12 ГБ с выгрузкой и 19 ГБ весов — в установку по умолчанию он не входит.

## Чего это стоит

Измерено на RTX 5060 Ti (16 ГБ), `nvidia-smi` опрашивался каждые 200 мс:

| Измерение | Значение |
|---|---|
| Простой после загрузки | 5,5 ГБ |
| Пик на 30-секундной песне | 6,9 ГБ |
| Песня 30 с по стенным часам | 12–15 с |
| Песня 45 с | 14–17 с |
| Загрузка модели | ~21 с (в процессе); первая песня после старта контейнера идёт ~170 с — дополнительно инициализируются токенизатор и LM |

Музыка — полноценная GPU-задача: очередь выгружает llama.cpp перед ней, а контейнер
перезапускается после, потому что CUDA-контекст сам по себе не освобождается. Это то же
правило, что у видеоконвейера.

## Что модели нужно от текста

Два правила следуют из замеров, а не из вкуса:

- **Разметка структуры.** Текст должен нести `[verse]`/`[chorus]`. Без неё те же русские
  строки дали полностью неразборчивый вокал (Whisper не находил речи); с ней слова
  возвращались с точностью 0,78–0,83.
- **Длительность должна соответствовать объёму текста.** Шесть строк на 30 с спелись;
  десять строк на 45 с дали 0,04–0,50, а шесть строк на 60 с заставили планировщик
  назвать трек инструменталом и выбросить вокал. Не больше 12 строк: замерено, 16 строк по-английски заставили модель повторять припев и
терять куплеты, поэтому более длинный текст отклоняется с просьбой разбить его. Ориентир —
около 6 секунд на строку: замерено, 16 строк при 5 с на строку закончились ровно
на запрошенных 80 с и обрезали последнюю фразу.

Клиент сам добавляет разметку, если её нет, и отказывает в длительности выше
`MUSIC_MAX_DURATION_S` вместо тихого ограничения.

## Хосты без GPU

Модель работает и на CPU, как заявляет upstream, но это тяжело и медленно — измерено на
12-ядерном хосте с образом без CUDA:

| Измерение | Значение |
|---|---|
| Инициализация модели | 74–77 с |
| Песня 10 с | 80–90 с (~8× реального времени) |
| Песня 30 с (экстраполяция) | 4–5 мин |
| RAM контейнера | 15 ГБ |

На 16-гигабайтном хосте это конкурирует с основной моделью, поэтому CPU — **осознанный
выбор**:

```bash
MUSIC_ALLOW_CPU=1 ./deploy.sh --with-music
```

Без этой переменной скрипт деплоя отказывает, называя цифры выше. CPU-стек собирает
`flai-music:cpu` из `services/music/Dockerfile.cpu` (колесо torch для CPU, без CUDA), а в
compose-файле нет резервирования GPU.


### XL 4B на карте 16 ГБ

Измерено: init 38,5 с, затем **CUDA OOM** на генерации — карта упёрлась в 15 794 МБ, задача
упала. Уровню XL нужно 24 ГБ либо явная выгрузка плюс INT8-квантование, что превращает
прогон в CPU-связанный (20-секундная песня на CPU шла 144 с). Поэтому установка по
умолчанию ставит пару 2B.

## Качество стохастично

Два прогона одной конфигурации дали 0,04 и 0,50 на длинной фикстуре. Один дубль ничего не
доказывает: для надёжного результата нужно генерировать двух кандидатов и оставлять
лучшего. Это записано в локальных заметках о проектировании; чат-путь пока так не делает.

## Проверка

```bash
docker compose --profile with-music up -d music
docker exec flai-music curl -fsS http://localhost:8001/health
curl -s http://localhost:5000/health | python3 -m json.tool   # "music": "ok"
```

Первый запуск скачивает веса; контейнер показывает `models_initialized: false`, пока не
прозвучит первая песня (модели загружаются лениво, ~21 с).
