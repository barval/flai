# Дорожная карта

Запланированная и ведущаяся работа над ПЛИИ. Недавно завершённое зафиксировано в [../CHANGELOG.md](../CHANGELOG.md); как подсистема ведёт себя **сегодня** — в том файле, который её описывает (см. Карту документации в [../AGENTS.md](../AGENTS.md)).

Этот список не является обязательством. Пункты переставляются, когда меняются приоритеты, а пункт может быть выброшен, если выяснится, что подход не тот.

## 🔄 В работе

- **Движок навыков (skills)** — именованные наборы способностей, расширяющие реестр способностей задач (`app/tasks/tools.py`): навык появляется ещё одним инструментом шага без изменений хранения (шов уже готов; см. [TASKS-ru.md](TASKS-ru.md))
- **Расширенная приоритизация очереди** — веса и защита от голодания для существующих классов пользователей (0/1/2) и классов задач (3/4/5)

## 📅 Планируется

- Архитектура плагинов для пользовательских модулей
- Поддержка нескольких GPU
- **Мультиплатформенная поддержка GPU** — расширение ПЛИИ для работы на не-NVIDIA машинах:
  - AMD / Intel через Vulkan для llama.cpp и stable-diffusion.cpp, ROCm для LTX-Video
  - Единый Docker Compose с профилями по платформам и env-управляемые скрипты деплоя
- **Альтернативные движки вывода LLM (исследование)** — оценить Strata, PolyStrata и другие
  локальные движки как возможное дополнение к llama.cpp + llama-swap: OpenAI-совместимая работа на
  Linux и в контейнерах, заявленная пропускная способность при малом VRAM (карты на 8 ГБ),
  поддержка мультимодальности и эмбеддингов, форматы моделей, лицензия MIT и риск поддержки.
  Результат — короткий отчёт с замерами на эталонном железе и решение «да/нет» по слою
  обслуживания моделей.

## Задокументированное поведение, о котором стоит знать

Это не пункты дорожной карты, а текущее поведение, которое удивляет людей достаточно часто, чтобы заслуживать отдельного упоминания:

- **Одна задача за раз на GPU.** ПЛИИ выстраивает в очередь все GPU-задачи за одним единственным замком и освобождает VRAM между ними. Поддержка нескольких GPU потребовала бы другой модели сериализации — поэтому она в разделе «Планируется», а не «В работе».
- **Окна контекста подбираются автоматически при развёртывании** по метаданным GGUF с диска и измеренным RAM/VRAM. Их не настраивают вручную. См. [CONTEXT-ru.md](CONTEXT-ru.md) и [VRAM_MANAGEMENT-ru.md](VRAM_MANAGEMENT-ru.md).
- **Решает роутер, а не ключевые слова.** Классификация запросов идёт через LLM-роутер; Python-фильтров по запросам нет. См. [ARCHITECTURE-ru.md](ARCHITECTURE-ru.md).
- **Tavily необязателен.** Без персонального ключа Tavily поиск в интернете целиком работает на локальном метапоисковике SearXNG. См. [SEARCH-ru.md](SEARCH-ru.md).
