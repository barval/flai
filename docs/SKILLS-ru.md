# Навыки — FLAI v13.6

Навык — это папка с инструкциями, которые модель загружает **по запросу**. В каждом
системном промпте лежит только строка каталога — имя и одно описание; тело читается
лишь тогда, когда модель решила, что оно нужно, и приходит как результат инструмента.
Именно поэтому навык дешёвый: хорошо написанный стоит одну строку контекста, пока его
не использовали.

Формат — тот же, что у Claude Code, opencode и pi, поэтому навык, написанный для любого
из них, работает здесь, и наоборот.

## Формат файла

```
skills/
├── web-research/
│   ├── SKILL.md        # английский, обязателен
│   └── SKILL.ru.md     # русский, необязателен
├── net-diagnostics/
│   ├── SKILL.md
│   └── SKILL.ru.md
├── documents/
│   ├── SKILL.md
│   └── SKILL.ru.md
└── svg-graphics/
    ├── SKILL.md
    └── SKILL.ru.md
```

```markdown
---
name: web-research
description: Собрать и перепроверить источники, прежде чем отвечать на вопрос.
allowed-tools: web_search, read_page
---
# Веб-исследование

1. Сделай один web_search по ключевым словам вопроса.
2. Открой два самых релевантных результата через read_page.
```

Понимаются три ключа:

| Ключ | Правило |
|---|---|
| `name` | `^[a-z0-9][a-z0-9_-]{0,63}$`, и он должен совпадать с именем папки |
| `description` | непустое, не длиннее 1024 символов — это строка каталога |
| `allowed-tools` | имена инструментов через запятую, проверяются при сохранении |

Имя папки **и есть** имя: поэтому дубликат невозможен, и поэтому панель отказывает в
имени, которое уже занято другим навыком.

Локализованный вариант (`SKILL.ru.md`) несёт собственный frontmatter, потому что
сканер читает каждый вариант тем же валидатором. Панель пишет этот frontmatter за вас:
вы вводите русское описание и текст, а имя копируется из английского документа.

## Две зоны хранения

| Зона | Путь | В git | В панели |
|---|---|---|---|
| Встроенные | `skills/` | да | видны, можно выключить, **нельзя изменить или удалить** |
| Установленные | `data/skills/` | нет | загрузка, создание, правка, включение, выключение, удаление |

Встроенные навыки поставляются вместе с проектом. Установленные пишет панель в
игнорируемое git дерево `data/`, поэтому установка навыка никогда не пачкает рабочую
копию и не уезжает в релиз случайно.

## Установка из панели

**Админ → Навыки**, сразу после **Модели**:

- **Загрузить .md** — один файл, не больше 64 КБ, UTF-8. Имя берётся из frontmatter.
- **Новый навык** — тот же редактор, пустой.
- **Изменить** — английский документ как обычный текст вместе с frontmatter, плюс
  русское описание и русский текст двумя отдельными полями.

Каждое сохранение прогоняет тот же валидатор, что и сканер, поэтому панель не может
записать навык, который сканер потом молча проигнорирует. Сохранение действует со
следующего сообщения: кэш сканирования сбрасывается, а не ожидается.

## Как навык попадает к модели

1. **Каталог** — `catalog()` рисует `- \`имя\`: описание` в системный промпт
   (`{skill_catalog}` в `chat.template`).
2. **Выбор** — ядро запроса называет подходящий навык в том же JSON-решении, где
   выбирает интент (не более двух), и только из имён, которые есть в каталоге.
3. **Загрузка** — `RedisRequestQueue._preload_skills()` дописывает тела в системный
   промпт этого запроса. Не как синтетический обмен с инструментом: по замерам тело,
   поданное как «инструмент уже сработал», заставляет модель отвечать по памяти вместо
   того, чтобы им пользоваться.
4. **Запасной путь** — навык, который модель вызвала напрямую через `activate_skill`,
   возвращает тело как результат инструмента. Этот инструмент объявляется только тогда,
   когда есть хотя бы один навык.

Навык никогда не перебивает конвейерные интенты: обход сайта, поиск по документам,
история, память и медиа-действия решаются до того, как рассматривается навык.

## Когда навык предлагается

Навык предлагается только пока существуют его инструменты. Если **все** имена из
`allowed-tools` отсутствуют в живом каталоге инструментов, навык не попадает в каталог,
который получает промпт: сетевая диагностика без сайдкара, чтение сайтов без краулера. Навык
без `allowed-tools` предлагается всегда: что ему нужно, решают его инструкции.

Права пользователя намеренно не входят в этот фильтр. Сетевые инструменты видны всем, кто
может общаться, вызов из учётной записи без разрешения отклоняется предложением, а первое
правило самого навыка — сказать это один раз и остановиться. Сокрытие по правам дало бы одной
идее две реализации: камера и MCP уже работают именно так.

## Что означают пометки инструментов

`allowed-tools` — это контракт, проверяемый при сохранении. Каждое имя попадает в один
из четырёх классов, и панель показывает в какой:

| Пометка | Значение | Блокирует сохранение |
|---|---|---|
| (без пометки) | инструмент есть в каталоге прямо сейчас | нет |
| *Здесь недоступен* | настоящий инструмент, чей сервис не запущен (`read_page` без краулера, `list_rooms` без камеры) | нет |
| *Неизвестный инструмент* | отличается от настоящего имени на одну опечатку — `web-serach` вместо `web_search` | **да**, с подсказкой |
| *Здесь недоступен* (чужой) | имя, которого в этой установке не было никогда — `Read`, `Bash(git:*)` | нет |

Четвёртый класс намеренный: навыки, написанные для Claude Code, перечисляют **его**
инструменты, и отказ из-за имени, которое корректно в другом месте, отвергал бы ровно
те файлы, для которых кнопка загрузки и существует.

Поле — **не** песочница: FLAI не сужает список инструментов до перечисленных в навыке.
Навык, который пишет «используй только `web_search`», сообщает модели свой замысел, а не
ограничивает её возможности.

## Выключение, удаление и перекрытие

- **Выключить** убирает навык из каталога, из перечисления `activate_skill` и из набора
  имён, которые может вернуть ядро. Файл остаётся. Флаг живёт в таблице
  `skill_settings` в PostgreSQL, а не во frontmatter — правка файла не может изменить
  поведение в обход панели.
- **Удалить** убирает установленную папку с файлами. У встроенного навыка кнопки
  удаления нет.
- **Перекрытие** случается, когда релиз приносит встроенный навык с именем, которое вы
  уже установили. Побеждает встроенный и показывается один раз; установленная копия
  остаётся на диске и помечается *перекрыт встроенным навыком* с кнопкой
  **Переименовать**. Переименование сохраняет документ под новым именем и удаляет
  старую папку только после успешного сохранения.

## Если навык не срабатывает

| Симптом | Что проверить |
|---|---|
| Навыка нет в промпте | он включён? Отдельной команды нет — ответ в колонке *Включён* |
| Модель его не выбирает | модель выбирает по описанию: называйте ситуацию, а не приём |
| Нет `activate_skill` | ни один навык не включён, поэтому инструмент не объявляется |
| Тело загрузилось, но ответ его игнорирует | тело читается как совет, а не как шаги — пишите нумерованные инструкции с именами инструментов |
| Русский вариант не используется | у него нет frontmatter или его `name` отличается; `SKILL.<lang>.md` без корректного frontmatter журналируется и пропускается |
| Сохранение отклонено с именем инструмента | это опечатка; сообщение называет инструмент, который имелся в виду |
