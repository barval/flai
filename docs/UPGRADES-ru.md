# Аудит обновлений зависимостей и платформ

Дата аудита: **26.10.2026**. Документ фиксирует, что устарело в поставляемом стеке, какие
обновления закрывают уязвимости, какие новые возможности upstream стоит принять в продукт и в
каком порядке выполнять обновления. Это входные данные для ветки
`features/v12.8-dependency-updates`, а не обязательство обновить всё сразу.

## Назначение

FLAI закрепляет небольшое число компонентов, а остальные подтягивает диапазонами версий. Аудит
отвечает на три вопроса одного релизного цикла:

1. Какие компоненты получили исправления безопасности, которые нельзя откладывать?
2. Какие обновления безопасны и механистичны, а какие требуют проверки совместимости?
3. Какие новые возможности upstream стоит принять в сам продукт?

## Как проводился аудит

- Установленные версии: `pip list --outdated` в виртуальном окружении разработки, `pip freeze`
  внутри работающего контейнера `flai-web`, `docker inspect` и команды версий запущенных сервисов.
- Опубликованные версии: JSON PyPI, API тегов Docker Hub и GHCR, релизы GitHub, `endoflife.date`
  для Python.
- Уязвимости: база OSV (`/v1/querybatch`) для установленных версий пакетов Python, а также
  заметки безопасности Redis и Crawl4AI.
- Влияние на код: `app/platform_detect.py`, `app/resource_manager.py`, `app/llama_swap_config.py`,
  `deploy.sh`, `docker-compose.gpu.yml` и Dockerfile сервисов.

## Возможности, которые стоит оценить

**llama.cpp (b11898)**

- `--spec-type ngram-simple|ngram-map-k|ngram-map-k4v|ngram-mod|ngram-cache` — спекулятивное
  декодирование без draft-модели. Перспективно на CPU и на картах AMD/Intel, где draft-модель не
  помещается в память.
- `--reasoning-budget-message` — текст, вставляемый перед закрытием thinking при исчерпании
  бюджета: более аккуратное завершение, чем текущая тихая остановка.
- `--cache-reuse N` — переиспользование KV через сдвиг для повторяющихся префиксов (системный
  промпт чата).
- `--metrics` — endpoint Prometheus на llama-server; можно завести во вкладку мониторинга.
- `/v1/responses`, `--models-dir` (router-сервер) — не нужны, эту роль уже выполняет llama-swap.
- Поле `reasoning_budget` в запросе по-прежнему не описано в API сервера, поэтому текущий
  CLI-обход (`--reasoning-budget max(1024, ctx*0.4)`) нужно сохранить и перепроверить.

**llama-swap (v260+ / v267)**

- Образы под каждый бэкенд: `cuda`, `cuda13`, `rocm`, `vulkan`, `intel` (SYCL), `musa`, `cpu`,
  плюс варианты `-non-root`. Это снимает блокер «собирать образы llama.cpp самим» для AMD и Intel.
- Capacity router (v267) не нужен: FLAI намеренно сериализует работу GPU.
- Образы `-non-root` — дешёвое улучшение безопасности контейнера моделей.

**Qdrant 1.20**

- BM25 прямо по full-text payload-индексу. Сейчас гибридный поиск склеивает dense-результаты
  Qdrant с полнотекстовым поиском PostgreSQL; нативный BM25 может убрать PostgreSQL из горячего
  пути. Мерить стендом из `docs/RAG_EVAL.md`: в PostgreSQL используется русский стемминг, а BM25
  только токенизирует, поэтому recall на русском может упасть.
- Типы векторов `turbo8` / `turbo16` — экономия памяти на эмбеддингах ценой части recall.
- Per-element payload-индексы — быстрее фильтры по `doc_id` и метаданным.
- Audit log в stdout/stderr — удобнее в контейнерах.

**Прочие компоненты**

- Crawl4AI 0.9.5 добавил deep-crawl на стороне сервера; FLAI сознательно держит BFS на клиенте
  ради контроля SSRF, поэтому это не принимается.
- Whisper 1.10.0 приносит новую базу CUDA и актуальные whisper/faster-whisper.
- Python 3.13 даёт производительность и лучшую диагностику; 3.14 — t-strings и отложенные
  аннотации. Для FLAI выигрыш скромный, а срок определяет поддержка зависимостей (gevent,
  psycopg2, qdrant-client); реалистичная следующая база — 3.13.
- Redis 8.6+ не даёт возможностей, нужных FLAI; смысл перехода — патч безопасности.

## Состояние мультиплатформенности

Пункт роадмапа **Multi-platform GPU support** реализован частично:

- `app/platform_detect.py` определяет `nvidia | amd | intel | cpu`, разбирает память AMD через
  `rocm-smi`, читает имя Intel GPU через `vulkaninfo` и учитывает override `FLAI_PLATFORM`.
  Вкладка Hardware в админке показывает результат.
- `services/sd_cpp/Dockerfile.sd_cpp` принимает `SD_BACKEND=cuda|vulkan|cpu`, обёртка SD
  учитывает бэкенд.
- Генерация изображений и видео деградируют в CPU при отсутствии CUDA.

Чего не хватает:

- `cuda_detected` равен `False` для AMD и Intel, поэтому менеджер ресурсов планирует их как
  CPU-хосты и ставит `n_gpu_layers=0`, даже когда `rocm-smi` сообщил объём памяти.
- `docker-compose.gpu.yml` и `deploy.sh` рассчитаны только на NVIDIA: `runtime: nvidia`,
  `NVIDIA_VISIBLE_DEVICES`, `SD_BACKEND=cuda`, `LTX_BACKEND=cuda`, профилей платформ нет.
- LTX-Video поставляется с CUDA-образом; для ROCm нужна база torch-ROCm и тестовый прогон.
- У Whisper нет ROCm-образа.
- Apple не может использовать Metal внутри Linux-контейнеров: для macOS нужен отдельный нативный
  путь установки (llama.cpp Metal, stable-diffusion.cpp Metal, whisper.cpp, CPU-сервисы).

Что изменилось у upstream: llama-swap теперь публикует образы ROCm, Vulkan и Intel для каждого
релиза, а бэкенды Vulkan, ROCm, SYCL и Metal в llama.cpp зрелые. Половина роадмапа, связанная с
llama.cpp и SD, поэтому близка; настоящая работа — LTX-Video и слой развёртывания.

### Этап 3, начало (v12.8)

- **Метрики Prometheus** — каждая сгенерированная команда `llama-server` теперь несёт `--metrics`,
  поэтому каждый бэкенд отдаёт `llamacpp:prompt_tokens_total`, `llamacpp:prompt_seconds_total` и
  остальные метрики на своём порту. Проверено на живом контейнере (`curl http://localhost:10003/metrics`
  внутри `flai-llamaswap`). Эндпоинт доступен только внутри сети Docker; вывод в вкладку «Мониторинг» —
  следующий шаг.
- **Исчерпанный бюджет размышлений завершается фразой** — команда reasoning теперь несёт `--reasoning-budget-message`, поэтому llama-server вставляет «Thinking budget reached. Stop analysing and answer now.» перед закрывающим тегом размышлений вместо молчаливой обрезки. Флаг виден и в сгенерированном конфиге, и в аргументах живого `llama-server` (одним аргументом, кавычки обрабатывает llama-swap); полное исчерпание бюджета не прогонялось.
- **Драйверы CUDA 12.x остаются поддержанными** — образ v267 по-прежнему несёт рантайм CUDA 12.8.1 и
  сохраняет `NVIDIA_REQUIRE_CUDA=cuda>=12.8`, как и v255, поэтому существующий обход не меняется:
  `deploy.sh` выставляет `LLAMA_SWAP_DISABLE_REQUIRE=1` для драйверов 12.2–12.7, а контейнер был
  перезапущен с `NVIDIA_DISABLE_REQUIRE=1`, чтобы подтвердить, что мультимодальная модель всё так же
  предзагружается и проходит проверку здоровья. `deploy.sh`, `deploy-ru.sh` и оба README теперь
  закрепляют v267 вместо v255, чтобы свежее развёртывание ставило ту же сборку, что и compose.

## Предлагаемая последовательность обновлений

Этапы сгруппированы в три релиза: **v12.8** берёт этапы 0 и 1, **v12.9** — этапы 2 и 3,
**v13.0** — этап 4.

**Этап 0 — база (без изменений кода, v12.8).** Сделать резервную копию PostgreSQL и тома Qdrant.
Зафиксировать базовый результат RAG-оценки, текущие показатели пропускной способности и лог
dry-load моделей. Добавить `pip-audit` и сканер образов в CI.

**Этап 1 — безопасность (v12.8).** Pillow 13, python-dotenv 1.2.4, urllib3 2.8, Werkzeug 3.1.9,
Redis 8.4.8, PostgreSQL 18.6, Crawl4AI 0.9.5. Добавить lock-файл и закрепить плавающие теги
образов. Критерий: загрузка и масштабирование изображений, рендер страницы PDF, импорт документа,
поиск и обход страниц, полный прогон очереди.

**Этап 2 — среда выполнения (v12.9).** Qdrant-сервер и клиент 1.20.0, gunicorn 26.2.0, gevent 26.9.0,
trafilatura 2.3.1, python-docx 1.2.0, psycopg2 2.9.13. Затем llama-swap v267 (или v260, пока
образов v267 нет) с llama.cpp b11898. Критерий: reasoning с бюджетом размышления, MTP-draft,
мультимодальность, вызовы инструментов, задачи, API `/v1`, RAG-оценка против базы этапа 0.

**Этап 3 — возможности (v12.9).** Сравнить BM25 в Qdrant с гибридом на PostgreSQL; попробовать
ngram-спекуляцию и `--cache-reuse`; завести `--metrics`; оценить `--reasoning-budget-message`.

**Этап 4 — платформы (v13.0).** Профили Compose и определение платформы в `deploy.sh` для AMD/Intel,
учёт VRAM для не-NVIDIA GPU, SD Vulkan, LTX ROCm. macOS остаётся отдельной исследовательской
задачей (нативная установка).

## Риски

- **llama.cpp b10991 → b11898** затрагивает шаблоны чата, разбор вызовов инструментов, обработку
  reasoning и мультимодальные проекторы. Обход бюджета размышления и логику повтора при 502 нужно
  перепроверить.
- **Qdrant 1.20** может мигрировать данные на диске; резервная копия тома обязательна перед
  первым запуском.
- **Pillow 13** — мажорный релиз с удалёнными API; нужно прогнать генерацию, редактирование, OCR
  и превью.
- **LTX-Video на новом PyTorch** может сломать загрузку модели; это отдельное изменение.
- **Отсутствие lock-файла** означает «что вышло на момент сборки»; lock и датированные теги
  образов — часть исправления, а не необязательное улучшение.

## Воспроизводимость

- `pyproject.toml` задаёт диапазоны почти для всех зависимостей; один и тот же коммит может дать
  разные окружения. Нужен lock-файл и установка из него в образе.
- `postgres:18-alpine`, `searxng/searxng:latest` и `python:3.11-slim` плавают. Закрепить точные
  версии или digest.
- stable-diffusion.cpp клонируется из `master` во время сборки. Закрепить commit и записать его в
  метку образа.
