# Генерация видео (LTX-Video 2B)

В проекте используется **LTX-Video 2B 0.9.8 distilled** для генерации видео:

| Модель | Шагов | Частота кадров | Разрешение | Примечания |
|-------|-------|-----------|------------|-------|
| **LTX-Video 2B distilled** | 8 | 24 fps | до 768×1344 | Дистиллированная, один GPU (~6 ГБ VRAM) |

Генерация видео выполняется в **отдельном GPU-контейнере** (профиль `--profile with-video`). Перед генерацией модель llama.cpp автоматически выгружается из VRAM, чтобы освободить память. После генерации кэш CUDA очищается, процессы LLM повторно выгружаются, а первичный контекст CUDA сбрасывается (`cuDevicePrimaryCtxReset`), чтобы вернуть всю GPU-память драйверу. Текстовый энкодер T5 (~8.9 ГБ в bf16) остаётся на CPU.

**Изменение размера исходного изображения:** при генерации видео из изображения оно передаётся в пайплайн LTX с максимальной стороной **768px** (уменьшает потребление VRAM и объём передачи). В чате отображается уведомление с исходными и изменёнными размерами.

**Подбор соотношения сторон:** при генерации видео из изображения разрешение выходного видео автоматически подгоняется под соотношение сторон исходного изображения: квадратное → 512×512, широкое (w/h > 1.2) → 768×512 (ландшафт), вертикальное (w/h < 0.8) → 512×768 (портрет).

**Необходимые модели:**
1. `ltxv-2b-0.9.8-distilled.safetensors` (~5.9 ГБ) — диффузионный трансформер + VAE
2. `PixArt-alpha/PixArt-XL-2-1024-MS` (текстовый энкодер/токенизатор) — энкодер T5-XXL (~18 ГБ на диске в float32, ~8.9 ГБ в VRAM в bf16)

```bash
# Загрузка через скрипт развёртывания
./deploy.sh --download-models --with-video

# Или вручную:
bash services/ltx_video/download-t5-encoder.sh
```

**Конфигурация:**
```bash
LTX_VIDEO_WRAPPER_URL=http://flai-ltxvideo:7872
LTX_VIDEO_MODEL=ltxv-2b-0.9.8-distilled
LTX_VIDEO_TIMEOUT=10800
```

**Только CPU:** планировщик (`plan_cpu_generation`) выбирает самый крупный формат, который влезает ОДНОВРЕМЕННО в доступную RAM и в бюджет времени (85% от `LTX_VIDEO_TIMEOUT`, если не задан `LTX_VIDEO_CPU_TIME_BUDGET_S`). Цепочка fallback: 768×512×240 → 384×256×120 @ 12 к/с → 256×192×57 @ 6 к/с → 256×192×24 @ 6 к/с. Оценки откалиброваны по измеренной скорости CPU (24 000 вокселей/с на шаг денойзинга; VAE-декод + сборка mp4 ~60 с на кадр с запасом на параллельную нагрузку хоста). Если не влезает ни один формат — запрос сразу отклоняется с локализованной ошибкой вместо таймаута посреди генерации.
