# Векторная графика в SVG

Используй этот навык, когда результат — **рисунок из фигур и текста**: схема
архитектуры или процесса, график, иконка, простой макет интерфейса, размеченный план,
анимированная объяснялка. Для фотографий, картин и персонажей, где важна текстура, а не
точные подписи, используй генерацию изображений. Для интерактивного результата (клики,
наведение, формы) используй обычный HTML.

## Как отдавать результат

Сохраняй рисунок документом:

```
write_document(name="Архитектура очереди", format="svg", content="<svg ...>...</svg>")
```

В вызове — обычные JSON-значения: `name` это имя файла, `format` — просто слово `svg`.
Никогда не вставляй внутрь вызова `<parameter>`, `<function=` и другие теги: модель, которая
заодно печатает вызов текстом, смешивает две формы, и сервер отклоняет значение.

Файл появляется в библиотеке документов, его карточка показывает изображение, а CSS-анимация
проигрывается прямо в предпросмотре. Не вставляй простыню разметки в чат — опиши результат
и дай предпросмотру показать его. SVG-документы не индексируются: разметка бесполезна для
поиска по документам.

Исключение — страница: если просят HTML-страницу, отдавай её блоком ```html в ответе.
У `write_document` нет формата html, такой вызов отклоняется.

`content` — законченный самодостаточный SVG-документ. Всегда указывай
`xmlns="http://www.w3.org/2000/svg"`, `viewBox` и явные `width`/`height`.

## Форма и компоновка

- Задай холст: схемы `800×600` или `1200×800`, иконки `24×24`, анимация `800×450`.
- Оставь поля 24–32 px. Выравнивай блоки и текст по сетке; подписи не должны пересекаться.
- Шрифт: `font-family="system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif"`.
  Схемы: 14–18 px; заголовки 20–24 px; в иконках текста нет.
- Экранируй `&` и `<` внутри текста как `&amp;` и `&lt;`; сырая разметка делает файл невалидным.

Минимальная схема:

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 360 120" width="360" height="120">
  <defs>
    <marker id="arrow" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="6" markerHeight="6" orient="auto">
      <path d="M0 0L10 5L0 10Z" fill="#475569"/>
    </marker>
  </defs>
  <g font-family="system-ui, sans-serif" font-size="14" text-anchor="middle">
    <rect x="10" y="40" width="90" height="40" rx="6" fill="#e0e7ff" stroke="#4f46e5"/>
    <text x="55" y="65">Роутер</text>
    <rect x="135" y="40" width="90" height="40" rx="6" fill="#dcfce7" stroke="#16a34a"/>
    <text x="180" y="65">Очередь</text>
    <rect x="260" y="40" width="90" height="40" rx="6" fill="#fee2e2" stroke="#dc2626"/>
    <text x="305" y="65">Модель</text>
    <path d="M100 60H130" stroke="#475569" stroke-width="2" marker-end="url(#arrow)"/>
    <path d="M225 60H255" stroke="#475569" stroke-width="2" marker-end="url(#arrow)"/>
  </g>
</svg>
```
- Небольшая палитра с сильным контрастом. Не передавай смысл только цветом.
- Стрелки: один `<marker>` в `<defs>`, дальше `marker-end="url(#arrow)"`.
- Связанные фигуры группируй в `<g>`; группе можно дать `id` для читаемости.
- Добавь `<title>` и `<desc>` для доступности.

## Графики

- Рисуй оси, деления, единицы и нулевую линию. Подписывай обе оси.
- Используй только те числа, которые дал пользователь; не выдумывай точки.
- Предпочитай столбцы, линии, точки или кольцо; никакого 3D и градиентов, скрывающих данные.
- Легенду ставь так, чтобы она не закрывала marks; порядок — в порядке чтения.
- При небольшом числе столбцов подписывай значение рядом; иначе достаточно оси.

## Иконки

- Сетка 24×24, `fill="none"`, `stroke-width="2"`, `stroke-linecap="round"`,
  `stroke-linejoin="round"`.
- Указывай явные цвета (`#1f2937`, `#2563eb`, …), а не `currentColor`: внутри `<img>`
  наследуемого цвета нет.
- Одна метафора на иконку; текст внутри иконки не нужен.

## Анимация

Используй CSS внутри элемента `<style>`. SMIL-анимация (`<animate>`, `<set>`,
`<animateTransform>`) отклоняется валидатором — не используй её.

```svg
<style>
  @keyframes pulse { 0%, 100% { opacity: 1; } 50% { opacity: .35; } }
  .pulse { animation: pulse 2s ease-in-out infinite; transform-box: fill-box; transform-origin: center; }
</style>
```

Анимируй `transform`, `opacity`, `stroke-dashoffset`, `fill` и `stroke`. Цикл короткий и
спокойный; для поворотов и масштаба задавай `transform-box: fill-box` и `transform-origin`.
Для пошаговой объяснялки используй `animation-delay`, а не скрипты.

## Что валидатор не пропустит

SVG — исполняемое содержимое, поэтому запись проверяется:

- нет `<script>`, атрибутов `on*`, `javascript:`;
- нет внешних `href` и `xlink:href` — только `#local-id`; никаких внешних картинок,
  шрифтов и таблиц стилей;
- нет `<foreignObject>`, `<iframe>`, `<object>`, `<embed>`, `<audio>`, `<video>`;
- нет `<!DOCTYPE>` и `<!ENTITY>`, нет `<?xml-stylesheet?>`;
- в CSS и презентационных атрибутах `url(...)` должен указывать на `#local-id`; нельзя
  `@import`, `@font-face`, `expression()`, `behavior:` и внешние URL.

Если запись отклонена — убери небезопасный элемент и попробуй снова. Не обходи проверку.

## Размер

- Держи один рисунок в пределах примерно 8 КБ разметки: несколько десятков элементов, а не
  фотография из кружков. По замерам сцена на 19 КБ генерировалась минутами и сломала собственный
  вызов инструмента; тот же сюжет на 5–7 КБ проходил с первой попытки.
- Лучше меньше крупных фигур и короткие повторяющиеся группы, чем тысячи координат.

## Перед ответом

- Каждая подпись помещается внутри своей фигуры при выбранном размере шрифта?
- Рисунок читается без цвета?
- Числа пользователя воспроизведены точно?
- Анимация только CSS и корректно зациклена?
- Файл самодостаточен — без CDN, внешних шрифтов и удалённых картинок?
